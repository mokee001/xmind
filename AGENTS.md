# Echoo implementation boundaries

- This is an independent implementation. Do not import/copy legacy business logic, selectors, template rules, models, caches or test outputs from sibling directories.
- Preserve the user's confirmed admission and theme rules in README.md and docs/DECISIONS.md. All admitted images enter daily; themes may overlap.
- Missing evidence, cloud-only previews, provider errors, refusals, truncation and unresolved conflicts cannot silently pass admission.
- Do not request photo authorization, enumerate the user's entire Photos library, set original-library fetch counts, enable iCloud downloads or publish/display finished artwork. Use caller-supplied assets and interfaces.
- Never modify, move, delete, relabel or overwrite source photos. Test-library paths are explicit runtime input, never legacy defaults.
- Production analysis must use shippable Apple frameworks or API providers. Conversation vision is not a runtime dependency.
- Vendor credentials belong only to the backend environment. No raw OCR/private strings in logs, reports, prompts or result caches.
- All Qwen-backed admission, theme, template scoring, pet identity and review calls use qwen3.8-flash, centrally selected in gateway/echoo_gateway/models.py. Legacy initial/review model environment overrides must not change this product choice.
- Native labels and preview quality metrics are evidence. Do not invent hard selection thresholds without validation against the agreed sample set.
- Each template owns its selection and layout strategy. Await the supplied design and confirmed constraints before implementing a concrete template; do not borrow old parameters.
- Every template must define both a standard and a fallback plan. Only explicitly confirmed hard requirements gate photo eligibility; unmet or unknown preferences do not. Follow the latest user-confirmed rules, not conflicting historical runtime checks.
- Blue-sky current rules are blue-sky-generation-rules-v3 in templates/pets.blue-sky-green-field/1.0.0/generation-rules.json. Runtime selection v3 uses pet evidence v2, original prompt v4 and cutout verification v2. Support cats, dogs, hamsters, parrots, turtles, goldfish and other common pets; do not use cat-only gates. Same-individual identity and distinct photos are required. Rank lexicographically by pose preference hits, composition/edge hits, known original general score, then stable IDs. Applicable confirmed hits are equal within each tier; do not invent cross-species normalization. technicalBasics informs general quality ratings, not an extra binary gate/bonus. Unknown/inapplicable preferences or missing scores do not block eligibility; unknown hard evidence cannot pass. Hide photo4, photo3, photo2, photo1, photo5 if needed; zero photos still render the background/fixed decorations without photo layers or outlines or model/segmentation calls. Source-edge completeness cannot become a hidden post-cutout gate. Admission is never bypassed. Offline tests/PNG output and iOS compilation are distinct from unverified real multi-species recognition/segmentation and device performance; do not claim production ready.

- Check relevant behavior with `sh scripts/test-swift.sh`, `sh scripts/check-ios.sh`, and `python3 -B -m unittest discover -s tests -v` from gateway. Clearly distinguish compilation/stub tests from real device/provider validation.
