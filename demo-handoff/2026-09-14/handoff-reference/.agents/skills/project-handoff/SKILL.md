# 项目交接

将可恢复的工作上下文与代码一起交接。技能不会复制完整聊天历史、进程、凭据或私人图库。以当前仓库为根定位文件，不假设另一台机器拥有相同绝对路径。

## 共同约定

- 先读取适用 AGENTS.md，检查实际仓库、分支、HEAD、工作树和远端；读取 `docs/handoff/` 中对应任务记录。记录可能过期，使用 Git 和本机状态验证。
- 每个独立任务用单独记录（如 `docs/handoff/onboarding-v22.md`），避免 App 和引导任务覆盖彼此。不要从任务标题猜工作区。
- 同一工作分支优先由一台电脑修改。记录接出/接入时间及设备标签只是协作提示，不是分布式锁。
- 技能本身不授予提交、推送、合并或发布权限。沿用会话中的授权；明确要求“交接并推送”可执行相应工作分支同步。若仅要求整理交接，保存文档即可。现有禁止推送或等待确认的约束优先。
- 只提交本任务已核对的文件，使用明确路径暂存；不自动纳入其他任务改动、照片、凭据或数据库。不强推、不覆盖本地修改、不为接手自动合并或变基。

## 接出：我要换电脑了，交接一下

1. 核对当前改动与任务边界，更新对应交接记录：目标、用户已确认的决定、未确认事项、已完成、下一步、验证与局限；记录分支、基准提交、未提交文件、外部依赖和预览入口。
2. 已获提交/推送授权时，将本任务代码与记录一起提交到约定工作分支。推送前检查远端与目标分支；如果 upstream 与当前分支名不同，不能默认推送 upstream，也不能猜目标。已有明确目标时使用显式 refspec。
3. 未获推送授权时完成本地交接记录，最后明确“尚未同步至另一台电脑”，给出需要授权的具体目标。不要把文档已保存称为交接成功。
4. 推送成功后，用远端分支实际 SHA 与本地 HEAD 核对；回复接手所需分支和提交 SHA。记录内不写无法预知的“包含自身的提交 SHA”；记录基准 SHA，最终交接 SHA 以推送结果为准。
5. 远端分叉、认证失败或网络故障时报告阻塞；不能声称已同步。保留本地工作，不进入反复推送或破坏性恢复。

## 接入：接着上次继续（明确跨设备语境）

1. 检查本机工作树与分支，读取本地记录；fetch 后读取目标远端分支上的交接记录，核对任务与提交，避免只依赖旧文档。
2. 已有工作树存在修改或分支分叉时，保留现场，说明冲突并确定接手方式；不自动 stash/reset/clean。状态安全且目标明确时，切换约定分支并仅快进更新。指定了工作区就使用该工作区。
3. 读取更新后的记录与适用规则，检查运行时、配置、忽略文件、仓库外脚本、媒体资源及占用端口。缺失依赖逐项报告；不因代码拉取成功便宣称环境恢复成功。
4. 仅按记录恢复本任务服务，验证页面或相关检查。共享服务必须先核实归属，不终止其他任务服务。不用替代数据冒充原数据，不自动重跑私人图库分析。
5. 简要回复已恢复的进度、待确认事项和下一步，然后按用户本次请求继续；若记录要求等待设计指令，保持等待。更新本任务接入记录。

## 持续记录

在使用本技能的任务完成实质性改动后，更新同一交接记录，区分“已实现”“已验证”“用户已确认”。这不等于每轮自动提交或推送。

记录建议包含：
- 更新时间、任务名、设备标签、交接状态
- 仓库标识、分支、基准提交、远端目标（未知就写未知）
- 目标和用户约束；已确认决定与待确认事项
- 已完成、未提交工作、下一步
- 实际执行的验证、时间与局限
- 本机依赖、启动方式、端口、缺失数据与迁移要求

首次引导的当前记录见 `docs/handoff/onboarding-v22.md`；处理其他任务时建立其独立记录，不套用引导任务特有的限制。
