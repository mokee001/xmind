# 回忆日历 App 完整 Demo · B v0.3.8

视觉与页面结构沿用用户选定的回忆日历版。2026-09-16 根据用户要求，将首次体验从欢迎页加四步设置，精简为两页；本次仍为 Demo，待用户查看。

## 入口

```sh
python3 -m http.server 8095 --bind 127.0.0.1 --directory demos/calendar-app
```

- 当前新用户体验：http://127.0.0.1:8095/?v=0.3.8#welcome
- 常规启动：http://127.0.0.1:8095/ （完成过设置则进日历，否则进欢迎页）
- 日历：http://127.0.0.1:8095/#calendar
- 桌面「从新用户流程体验」和设置底部「重新体验新用户流程」会新建引导草稿，保留原已保存偏好。
- `#setup`、`#setup-permissions` 兼容到欢迎页；旧 `#setup-preferences`、`#setup-schedule` 兼容到连接页，照片未授权时返回欢迎页。

## 两页主线

1. **欢迎与照片授权**：欢迎页直接点「授权照片，开始使用」。允许全部或部分照片均可继续；拒绝保留本页并可重试。
2. **连接照片墙**：按需请求蓝牙、本地网络，自动查找设备。点击发现的设备直接进入 Wi-Fi 选择，不再重复确认。联网成功自动保存，接着完成首幅模拟上屏，再进入日历。

不再前置人物、主题或更新时间设置。新用户沿用现有默认：自然安排、每天20:00更新；之后可在偏好和设置中调整。重新体验时保持既有偏好、频次、时间与设备名称，完成只更新连接与照片授权字段。

## 返回与失败

连接页可返回欢迎页，已授予权限保留；离开页面或重新体验会取消未完成的查找、连接和自动保存回调。连接失败可重试。保存失败停在已连接页，可以重试保存而无需重新配网。手动保存会取消待执行的自动提交，避免失败后再次自动提交。

## 首次准备并行与恢复（2026-10-11，v0.3.7）

照片授权后在后台启动本地模拟准备，与配网并行；连接与保存成功后复用已完成准备。服务候选就绪即可生成首幅，不等待完整首批上传；其余模拟上传等首幅回执成功后才继续，避免与首次生成投送争用资源。准备尚未完成时仍继续等待，不假造完成。上传异常重试保留准备，回执异常重试仅重新等回执，不重做上传、生成与投送。

完整入口 `http://127.0.0.1:8095/?v=0.3.7#welcome`；`?firstWall=preparation-slow#welcome` 可查看连接后准备尚未完成。桌面手机框外提供事件说明与摘要，手机内不增加整理进度或操作。全部是模拟事件协调，不是实测耗时改善，尚未发布 App。详细机制、参考锁定及验证见 `docs/first-wall-fast-demo-v0.3.7.md`。

## 人物偏好恢复（2026-10-12，v0.3.8）

入口 `http://127.0.0.1:8095/?firstWall=people#first-wall`，约 7 秒模拟准备后显示「需要重新确认人物偏好」。
主按钮进入原有偏好页并直接管理；「重新检查」保留同一错误、选择与连接，不会因重试自动清除人物约束。
该场景模拟本期精选没有可选人物：原选择与明确标注的旧选择示例列为「待确认的旧选择」，不显示正常 Demo 的六个人物气泡。
用户需逐项明确移除旧选择，页面随后说明「未选择人物，保存后按自然安排继续」。不调整可返回保留原选择。
保存失败保留草稿；保存成功才回首次页，复用已完成步骤并继续生成、投送与模拟回执。

直达场景的连接与照片授权仅覆盖内存，不写入既有本地设置；进入恢复页不会改写已保存偏好，只有明确保存后才写入 Demo 偏好。
设备名、更新时间、主题偏好等沿用已有值。正常偏好页仍为管理后编辑、保存后只读。全流程不读取图库、不上传照片、不连接真实设备。

视觉锁为现有日历 Demo 的暖色画布、黑色主按钮与原偏好页；错误原位说明及修复操作依据 Refero `craft-details.md` 的表单错误处理规范。
验证 `node --test tests/test_first_wall_demo.mjs`：14 项通过，覆盖无可选人物、显式取消、有当前人物时重新选择、返回未保存、保存失败后恢复、正常偏好行为与原首次上屏流程。

## 服务连接恢复预览（2026-10-10，v0.3.6）

- 完整故障体验：`http://127.0.0.1:8095/?connection=cloud-offline#welcome`。
  按两步流程完成模拟授权和连接后，Wi-Fi 保留，服务最多尝试三次，随后停在「暂时连不上服务」。
  点击「重试连接服务」仅重试服务，持续故障不会自动变成成功；不要求重新输密码或删除设备。
- 在「连接帮助」中点「模拟服务恢复」，再重试可进入原有首次准备流程；正在重试时会自动继续。
  `connection=cloud-temporary` 演示第三次服务请求恢复，`connection=wrong-password` 演示独立的密码错误。
  密码错误可先在帮助中「模拟密码已更正」，再重新连接。全部为本地示例，不收集密码。
- 换网只由用户主动选择；返回、离开或模拟 Wi-Fi 断开会取消原来的待执行回调。
  刷新故障页保留模拟 Wi-Fi 状态，不误报整条连接完成。保存失败仍只重试保存。
- 不改日历、选片、照片权限、已保存偏好、更新时间与设备名；真实 App 尚未迁移本次恢复页面。
  固件恢复候选在独立 E1002 worktree 验证；Demo 不代表硬件已恢复联网或已上屏。

设计以用户已确认的 `demos/calendar-app/` 页面为锁定参考，保留原色彩、字体、两步结构和主按钮。
恢复状态仅压缩标题与图标占高，保证窄屏能看到具体原因与操作。微文案、内联状态与焦点规则参考
Refero skill 的本地 `copywriting.md`、`craft-details.md`；线上 Refero 检索返回订阅不可用，未冒称已取得外部案例。
测试：`node --test tests/test_connection_recovery_demo.mjs tests/test_first_wall_demo.mjs`。
