# 回忆日历 App 迁移 · 2026-09-16

用户确认以 `demos/calendar-app` v0.3.0 为 App UI 与框架，并明确保留正常设备连接流程。本次按已确认 Demo 迁移，不使用后续视觉探索。

## 参考锁定

| 决策 | 依据 | 实现边界 |
| --- | --- | --- |
| 无底部 Tab，首页为纵向日历 | 已确认 calendar-app/style.css 与 app.js | 日期按手机本地时区；只收设备已确认的展示记录 |
| 左上常驻连接，右上偏好与设置同级 | 用户已确认结构 | 绑定与实时心跳区分；状态入口继续调用原设备管理 |
| 暖纸底、宋体标题、淡线和克制按钮 | 日历 Demo v0.3 | 不引入探索版素材或假照片 |
| 首次仅授权照片与连接两步 | v0.3 短引导 | 真实系统授权、BLE 发现、Wi-Fi 配置与绑定保持；连接完成后保存并进入日历 |
| 先使用默认偏好 | 用户的零手动挑片目标 | 已有已保存快照原样保留；新设备中性默认，每天20:00；整理在后台继续 |
| 旧整墙管理能力保留 | 合并不覆盖现有功能 | 移入设置的照片墙管理，不作为首页 |

## 连接与数据约束

- `src/bleProvisioning.js`、`src/deviceApi.js`、`src/sessionStore.js` 和真实连接适配器不替换；不改服务 UUID、超时、配网协议或账户/设备接口。
- `DeviceSetupFlow` 的自动结束仅用于首次引导，在真实配网和绑定成功后调用既有 `finish → await onConnected → onClose`。每个成功结果只尝试一次，持久化失败仍可手动重试。新增设备与重新配网保留原完成方式。
- 自动完成等待当前绑定的偏好恢复；保存与后台整理隔离切设备、换绑定后的旧回包。
- 没有设备回执不生成历史。当前 history 接口仅提供标题、时间、revision，不返回历史照片；日历使用记录标记与文字详情，不伪造缩略图。
- 页面结构迁移不改变照片筛选、模型、权重、主题聚合或模板目录。
