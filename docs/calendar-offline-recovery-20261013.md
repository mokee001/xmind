# 日历网络异常与设备管理恢复 · 2026-10-13

## 本次问题

用户在正式 App 的回忆日历中一直看到“确认连接中”和“正在读取展示记录…”，并报告设备无法删除。截图是日历首页，不能据此认定首次生成仍在运行，也不能仅凭等待动画认定 JavaScript 主线程卡死。

代码中展示历史、偏好及账户初始化的请求缺少包含响应体读取在内的时限；设备删除也会长时间占用操作状态。历史刷新在成功返回前清空旧结果，状态读取失败没有独立的服务访问提示。状态轮询曾在两次权限或设备缺失错误后清除本机绑定；然而现有设备列表接口对无效凭据也可能返回空列表，不能据此确认解绑成功。

## 修复边界

1. 日历、状态、偏好和账户读取设置 8 秒时限，覆盖请求和响应体。超时结束加载并允许重试；同一绑定已读取的历史保留，读取失败不能显示为“没有记录”。
2. 分开表示手机无法访问服务与服务确认的屏幕离线。服务请求失败时屏幕状态未知；过期心跳时提醒检查屏幕电源和 Wi-Fi，历史记录仍可读取。
3. 等待期间保留返回日历、偏好、设置与设备管理入口。首次准备沿用原任务与上屏回执核对，不以重试代替确认，也不新增选片操作流程。
4. 设备移除与重新配网请求设置 10 秒时限。只有目标设备匹配、明确成功的回执才清理本机会话；超时、权限错误、空设备列表或异常响应均不冒充成功。
5. 关闭设备管理不解除正在进行的操作锁。存储队列中的旧任务必须重新核对绑定与操作代次，避免迟到响应覆盖新绑定或恢复已移除会话。
6. 不修改精选模型、阈值、聚合规则、照片范围、配网实现或已确认的人物偏好。
