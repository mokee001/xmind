# 回忆日历首次体验精简 · Demo v0.3.0

## 设计依据与边界

用户已选定8095回忆日历，现要求前置流程缩短。主参考为原有 calendar-app 欢迎页与日历的字体、纸色、间距、按钮和导航；遵循 Refero existing-UI/direct-build 路径，不进行新视觉探索。

保留现有纸色背景、宋体标题、黑色主按钮、左上返回、两步进度；减少页面、设置和重复确认。仅改Demo，真实权限和连接仍未接入，原选片、人物策略与App均不改。

## 决策

- 两页：欢迎页直接请求照片授权；第二页按需申请连接权限、发现并连接设备。
- 用户明确点击发现设备的连接按钮后直接选择Wi-Fi，不再二次确认同一台设备。
- 联网完成自动保存进入日历，不增加完成页或额外确认。
- 不在引导中选择人物、主题、更新时间。新用户沿用现有默认：自然安排、每天20:00。已有设置保持，重新体验不重置偏好或更新时间。
- 原权限、偏好、时间hash兼容引导到对应必要步骤；不允许跳过照片授权和设备连接就标记完成。
- 拒绝/失败有重试；保存失败停在已连接页重试保存，不重连；返回/离开取消异步回调。
- 欢迎页仍可查看连接前准备；偏好和更新时间由日历上的既有同级入口后续调整。

旧完整源码：outputs/calendar-app/v0.2.0-before-short-onboarding-20260916/source.tar.gz。

## 验证结果

393×852浏览器实测：两步进度；照片拒绝不前进、部分授权可继续；蓝牙拒绝可重试；设备选择直接进Wi-Fi；连接途中返回停留欢迎；完成自动进入日历；设置仍显示原每天20:00。

9项VM行为回归通过，见 `outputs/calendar-app/short-onboarding-audit-20260916.txt`。修复了手动保存失败时残留自动保存计时器会二次提交的竞态；完成只写connected/photoAccess，避免覆盖已有偏好/时间/设备名。

最终320×740目检通过，主按钮完全可见；document宽度与scrollWidth均320，无页面横向溢出。
