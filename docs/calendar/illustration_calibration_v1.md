# AI 手帐日历插画与文字专项校准规范 v1

## 1. 为什么当前 7 月日历没有出现这些模式

当前 7 月日历中，有素材的 22 个日期都能选到合格照片，因此优先保留真实照片。其余 9 个空白日期没有用户文字、OCR 记录或可靠事件信息，按照“不编造生活内容”的原则保留了空白。

这不代表插画、纯文字和插画加文字不重要，而是此前缺少一套足够明确的触发规则、文字证据字段和专项案例。当前专项校准的目标，就是让系统在出现合适输入时稳定选择以下三种模式：

- `illustration_only`：无图片插画。
- `text_only`：纯文字。
- `illustration_with_text`：无图片插画加文字。

`blank` 同时作为重要反例标签，防止系统为了填满日历而编造内容。

## 2. 当前阶段的“训练”是什么

当前不训练模型权重，采用以下方式校准 GPT Vision：

1. 冻结处理标签和结构化字段。
2. 写清触发条件、禁用条件和文字证据规则。
3. 建立正例、反例与边界案例。
4. 让同一批案例反复通过提示词判断。
5. 比较预期标签和模型结果，修改规则与提示词。
6. 当案例量和人工修订数据足够后，再考虑微调或训练分类模型。

这一阶段产生的数据可以直接作为 2.0 后续训练数据。

## 3. 四类决策

### 3.1 留白 `blank`

使用条件：

- 当天没有合格照片。
- 没有用户文字、OCR 文字或可靠事件证据。
- 只有系统噪声、广告、垃圾信息、二维码或无上下文语气词。
- 插画会把模糊内容解释成具体事件。
- 整月版面需要呼吸感。

默认规则：

> 没有证据时默认留白，不默认添加插画。

### 3.2 无图片插画 `illustration_only`

固定规格：

- 插画区域：54×63。
- 日期格 padding：1。
- 风格：`journal_line_doodle_v1`。
- 不显示文字。

适用条件：

- 当天没有合格照片。
- 当天没有应当展示的有意义文字。
- 包含当前日期在内，至少有 2 个连续空白日期。
- 整月布局需要打断连续空白。
- 插画只承担视觉填充，不代表当天真实发生的事件。

例子：

- 花朵或花瓶。
- 滑板、茶杯、面包等日常物件。
- 太阳、云、月亮等天气或自然图形。
- 猫、鸟或普通人物动作。

硬性限制：

- 插画可以与当天事件无关，但不能制造“当天真的发生过这件事”的误解。
- `illustration_role` 必须为 `decorative`。
- `layout_balance_needed` 必须为 `true`。
- `consecutive_blank_run_length` 必须大于或等于 2。
- 如果存在有意义文字，改用 `text_only` 或 `illustration_with_text`，不能隐藏文字只保留插画。

### 3.3 纯文字 `text_only`

固定规格：

- 文字框：52×62。
- padding：2。
- 字体：`momozhuanji`。
- 字号：10。
- 字重：600。
- 最多 24 个汉字。
- 推荐 3–6 行。

适用条件：

- 当天没有合格照片。
- 文字措辞本身是这一天的主要记忆。
- 内容细腻、抽象或具有个人语气。
- 插画会削弱、误读或过度简化文字。

例子：

- “天啊，东野圭吾去世了，我最喜欢的小说家”。
- “怎么才周四，好期待周末啊”。
- “痛经真的很难，得好好休息”。
- 一段不能安全转化为单一物件的复杂感受。

### 3.4 无图片插画加文字 `illustration_with_text`

固定规格：

- 插画区域：54×50。
- 文字区域：52×14。
- 字体：`momozhuanji`。
- 字号：8。
- 字重：600。
- 文字最多 14 个汉字。
- 推荐 1–2 行。

适用条件：

- 当天没有合格照片。
- 有可靠且简短的文字记录。
- 短文字保留用户语气或事件重点。
- 一个简单插画可以补充视觉线索。
- 插画和文字互相补充，而不是重复表达同一件事。

例子：

- “痛经躺了一天，还是睡觉好” + 躺下休息的人物线描。
- “朋友捡的猫咪，看起来好聪明” + 猫咪线描。
- “终于下班啦” + 公文包或时钟。

不适用条件：

- 文字超过 14 个汉字且不能安全压缩。
- 插画主体无法从证据中确定。
- 文字本身已经足够完整。
- 插画会加入用户没有表达的情绪或事件。

## 4. 决策树

```text
是否有合格照片？
  ├─ 有 → 优先使用图片处理类型
  └─ 没有
      ↓
是否有可靠文字或事件证据？
  ├─ 没有
  │   ├─ 至少 2 个连续空白且布局需要打断空白 → illustration_only
  │   └─ 否 → blank
  └─ 有
      ↓
文字中是否有可安全绘制的具体物件、动作、人物或动物？
  ├─ 有，且可压缩为 14 字以内 → illustration_with_text
  └─ 没有、内容抽象或信息较复杂 → text_only
```

## 5. 文字证据规则

来源优先级：

1. `user_caption`：用户主动输入。
2. `manual_annotation`：人工标注。
3. `ocr_note`：笔记 OCR。
4. `ocr_chat`：聊天 OCR。
5. `ocr_system_screenshot`：有生活意义的系统截图 OCR。
6. `ocr_web_content`：与用户重要事件、个人感想或身体状态有关的网页内容。
7. `reliable_event_metadata`：可靠事件元数据。
8. `model_summary`：仅允许事实性摘要。

必须记录：

- `text_source`：文字来源类型。
- `text_source_excerpt`：支撑短文字的原始片段。
- `text_is_direct_quote`：是否为用户原话。
- `short_text`：最终显示文字。

禁止：

- 把模型总结放进引号，伪装成用户原话。
- 推测用户的情绪、关系或活动。
- 增加不存在的地点、金额、时间和人物身份。
- 展示手机号、地址、订单号、付款信息和第三方隐私。

网页内容的额外规则：

- 网页截图原图不进入日历格。
- 用户上下文明确表明内容与自己有关时，可以忠实提炼成短文字。
- 普通新闻、教程、广告或与用户无关的网页内容必须排除。
- 不得把网页中的事实改写成用户亲身经历。

## 6. 插画风格 `journal_line_doodle_v1`

### 6.1 视觉特征

- 单色深灰线描，颜色 `#202020`。
- 透明背景。
- 线条自然、略不均匀，保留手绘感。
- 轮廓优先，内部细节少。
- 允许少量实心黑色块作为手绘强调。
- 主体周围保留明显留白。
- 小日期格中一眼可辨。
- 最多 1 个主主体和 1 个很小的辅助物件。
- 构图采用局部特写或单一视觉焦点，只保留最能表达当天事件的部分。
- 人物不画全身，只使用头像、面部、头肩、上半身，或手、脚、耳朵等动作相关局部。
- 物品突出一个核心物件或关键部位，不描绘完整环境场景。
- 可以有少量作为画面细节的手写标签。

### 6.2 禁止风格

- 写实照片或半写实插画。
- 3D、黏土、像素或复杂卡通渲染。
- 复杂彩色填充、渐变和阴影。
- 高密度场景和复杂背景。
- 人物全身构图。
- 多主体叙事和完整环境场景。
- 品牌 Logo、二维码和条形码。

日历要表达的重要文字必须放在独立文字区域，不能依赖插画内部的小标签。

新增特写参考图：

```text
training/illustration_text/references/closeup_single_focus_reference.png
```

参考图中的茶杯、食物、耳朵、脚、手、眼睛等案例说明：插画不需要完整复述场景，只需要抓住最有辨识度的物件或身体局部。人物类即使表达活动，也不能退回全身小人构图。

### 6.3 当前执行策略

当前 MVP 使用设计师插画库：

```text
GPT Vision
  ↓
输出 illustration_category + illustration_brief
  ↓
本地插画库按标签匹配
  ↓
本地执行器按固定尺寸放入日期格
```

当前不让模型自由生成插画。后续只有在设计师确认风格样本后，才考虑把生成插画作为兜底。

## 8. 模型输出要求

无图片模式除通用字段外，必须输出：

- `text_source`
- `text_source_excerpt`
- `text_is_direct_quote`
- `text_layout`
- `illustration_role`
- `illustration_category`
- `illustration_style_id`
- `illustration_brief`
- `layout_balance_needed`
- `consecutive_blank_run_length`

固定组合：

| 处理方式 | 文字 | 插画 | text_layout | element_count |
|---|---|---|---|---:|
| `blank` | 否 | 否 | `none` | 0 |
| `text_only` | 是 | 否 | `full_cell` | 1 |
| `illustration_only` | 否 | 是 | `none` | 1 |
| `illustration_with_text` | 是 | 是 | `bottom_band` | 2 |

额外组合限制：

- `illustration_only`：`illustration_role=decorative`、`layout_balance_needed=true`、`consecutive_blank_run_length>=2`。
- 其他模式：`consecutive_blank_run_length=0`。

## 9. 专项评测指标

- 四分类准确率。
- `blank` 误填充率。
- 文字来源可追溯率。
- 文字隐私泄露次数。
- 第一人称内容编造次数。
- 插画类别命中率。
- 插画与文字语义重复率。
- 插画风格违规次数。
- 文字长度和排版超限次数。

硬性目标：

- 编造事件或情绪：0。
- 隐私泄露：0。
- 二维码、付款码进入内容：0。
- 无证据日期被写入具体生活事件：0。
- 最终月历中连续空白日期：0；任意空白日期前后不得再紧邻空白。

### 9.1 连续空白修复规则

- 单个空白日期允许保留。
- 两个及以上连续空白日期必须被中性装饰插画打断。
- 修复后连续空白的最大长度为 1 天。
- 优先在连续空白段的中间日期放置 `illustration_only`。
- 若需要同时改善月末收尾或版面节奏，可使用 `illustration_with_text`，但文字只能是季节、时间或月度收尾类通用短句。
- 通用填充不得暗示用户当天发生了具体事件，不得伪造情绪、地点、人物关系或第一人称经历。

## 10. 下一轮校准方法

1. 使用 `training/illustration_text/calibration_cases_v1.jsonl` 跑第一轮。
2. 对每个错误记录“模型输出、人工预期、错误类型、修改建议”。
3. 优先修复 `blank` 与其他三类之间的误判。
4. 再修复 `text_only` 与 `illustration_with_text` 的边界。
5. 最后校准插画类别和文字压缩。
6. 至少积累 100 个真实案例后，再评估是否需要训练分类模型。
