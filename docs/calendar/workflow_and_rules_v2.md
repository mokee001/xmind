# AI 手帐日历：当前工作流与规则 v1

版本日期：2026-07-29

> 本文为历史版本。当前完整实现请查看 `AI手帐日历_整体技术实现方案_v2.md`。

## 1. 当前目标

输入一个月份的真实照片，自动整理并生成具有生活感、手帐感的月历。

核心原则：

> AI 不创造或重绘用户照片，只负责需要审美判断和灵活推理的决策；本地程序负责确定性处理、校验和渲染。

当前阶段不接 OpenAI API，使用会话内 GPT Vision 完成图片处理决策。未来需要批量自动化时，再把相同规则、提示词和输出结构接入 API。

## 2. 当前技术分工

| 层级 | 当前实现方式 | 是否使用 AI |
|---|---|---|
| 照片选择层 | 沿用已经验证合格的现有选图流程 | 沿用原方案 |
| 图片理解层 | 沿用现有视觉理解结果 | 沿用原方案 |
| 图片处理决策层 | GPT Vision 根据规则选择处理方式 | 是，当前重点 |
| 图片处理执行层 | 本地裁切、遮罩、抠图、文字和组合算法 | 否 |
| 整月布局层 | 当前先使用模板与确定性规则；后续引入 GPT Vision 生成候选布局 | 后续使用 |

总原则：

```text
AI 负责理解和判断
规则负责约束和验收
本地算法负责执行
```

## 3. 完整工作流

```text
01. 导入一个月的照片
02. 从文件名或照片信息读取日期
03. 排除明确不可用素材
04. 检测重复、连拍和同场景照片
05. 沿用现有方法完成每日选图
06. 沿用现有方法生成视觉理解结果
07. GPT Vision 判断每个日期的图片处理方式
08. 本地程序检查 GPT Vision 输出是否符合硬规则
09. 本地程序执行裁切、圆图、椭圆图、抠图、文字或插画组合
10. 生成每个日期的处理后素材
11. 按模板规则生成整月布局
12. 检查日期归属、遮挡、越界、碰撞和图片质量
13. 输出最终月历和过程报告
```

## 4. 输入与日期

### 4.1 输入素材

优先支持：

- JPG
- JPEG
- PNG
- WEBP

需要在导入阶段排除：

- MOV、MP4 等视频
- 动态 GIF
- 无法读取或损坏的图片

### 4.2 日期读取

真实照片优先读取 EXIF 拍摄日期。

下载图片或日期不可靠的测试图片使用文件名：

```text
2026-07-12__001.jpg
2026-07-12__002.jpg
```

文件名中的 `2026-07-12` 直接作为日历归属日期。

硬规则：

- 照片只能进入所属日期。
- 不得为了版面效果把照片移动到其他日期。

## 5. 素材过滤规则

### 5.1 必须排除

- 二维码
- 条形码
- 付款码
- 快递单
- 纯文字网页截图
- 黑屏或几乎全黑
- 严重模糊
- 严重过曝
- 严重欠曝
- 视频文件
- GIF 或动态图片

### 5.2 特殊保留规则

- 手机系统截图或聊天记录能表达用户心情，且当天没有更合格照片时，可以转成纯文字日历格。
- 票据涉及购物、奶茶、蛋糕等生活事件时，可以作为辅助素材。
- 海报、电影、影视、游戏和音乐专辑截图能反映娱乐生活时，可以保留。
- 构图普通但记录重要活动的照片可以保留。
- 普通食物、工作成果和购物记录可以保留，但降低选择优先级。

## 6. 每日选图规则

当前选图方法已经达到可用标准，继续沿用，不在本阶段重新开发。

同一天照片的内容优先级：

```text
人物或合照
→ 宠物
→ 特定活动
→ 食物
→ 风景
→ 小物件
→ 构图最好
→ 工作或学习成果
```

综合判断优先级：

```text
审美
→ 生活意义
→ 活动事件
→ 人物关系
→ 模板适配
→ 技术质量
```

补充规则：

- 人物照片优先。
- 同一天原则上选择 1 张主图片。
- 最终处理允许使用辅助图片，但单个日期最多 3 张。
- 没有合格照片时允许留白。
- 整个月照片少时接受较多留白。

## 7. 图片理解结果

图片理解层沿用现有方法，建议至少提供：

```json
{
  "image_id": "2026-07-12__001",
  "content_type": "person",
  "description": "人物在草地上奔跑",
  "main_subject": "全身人物",
  "subject_bbox": [0.30, 0.18, 0.72, 0.96],
  "people_count": 1,
  "background_value": 0.82,
  "crop_safety": 0.76,
  "cutout_suitability": 0.61,
  "small_cell_readability": 0.84
}
```

处理决策层读取这些结果，不重新完成选图排序。

## 8. GPT Vision 图片处理决策

### 8.1 输入

GPT Vision 每次读取一个日期的素材：

```text
当日已经选中的 1-3 张图片
+ 原有视觉理解结果
+ 图片处理规则注册表
+ Figma 正例和反例
+ 日期格和模板约束
```

### 8.2 GPT Vision 负责判断

- 使用哪一种固定处理类型。
- 哪张是主素材，哪些是辅助素材。
- 是否保留背景。
- 裁切重点是什么。
- 是否适合圆形或椭圆形裁切。
- 是否适合单主体或多主体抠图。
- 是否需要短文字或插画。
- 建议锚点和旋转角度。
- 备选处理方式。
- 置信度、命中规则和风险。

### 8.3 GPT Vision 不负责

- 重新选择其他日期的照片。
- 生成或重绘照片内容。
- 自定义处理类型。
- 修改固定尺寸、字体、安全区或极限区。
- 输出最终整月画布坐标。
- 绕过本地硬规则检查。

### 8.4 输出

输出结构示例：

```json
{
  "decision": "USE",
  "treatment_mode": "irregular_cutout",
  "fallback_treatment_mode": "proportional_full_image",
  "confidence": 0.88,
  "selected_asset_indices": [1],
  "primary_asset_index": 1,
  "element_count": 1,
  "main_subject": "人物半身",
  "subject_bbox": [0.18, 0.10, 0.84, 0.96],
  "anchor": "bottom_right",
  "overflow_level": "safe_zone",
  "rotation_degrees": -3,
  "crop_focus": "保留头部、双手和手中物品",
  "keep_background": false,
  "text_required": false,
  "short_text": "",
  "illustration_required": false,
  "illustration_brief": "",
  "matched_rule_ids": ["irregular_cutout"],
  "reasons": ["人物主体明确", "背景价值较低"],
  "risks": ["头发靠近顶部边缘"]
}
```

## 9. 图片处理全局硬规则

1. 原则上每个日期使用 1 张图片。
2. 单个日期图片数量最多不超过 3 张。
3. 没有图片的日期允许留白，也允许使用线描插画。
4. 可以为了主体表现和美观进行裁切。
5. 左右旋转角度绝对值不得超过 10 度。
6. 在满足硬约束的前提下，以整体美观为首要标准。
7. 异形抠图不得增加白色描边。
8. 异形抠图不得增加阴影。
9. AI 选择的素材索引必须真实存在。
10. 图片处理失败时必须使用备选处理方式，不得让整个日期渲染失败。

## 10. 固定处理类型

### 10.1 比例内完整图片

类型 ID：`proportional_full_image`

固定规格：

- 宽高：54×63
- 与日期格 padding：1
- 默认保留背景和完整画面

适用：

- 风景
- 完整环境
- 人物全身
- 演出照片
- 背景或完整构图具有意义

### 10.2 无图片插画

类型 ID：`illustration_only`

固定规格：

- 宽高：54×63
- 与日期格 padding：1
- 风格：线描插画

适用：

- 当天没有合格照片
- 需要少量装饰填充
- 原始纯文字截图不适合直接展示

当前插画应来自提供的插画素材库；GPT Vision 只给出插画主题建议。

### 10.3 无图片插画加文字

类型 ID：`illustration_with_text`

固定规格：

- 插画：54×50
- 文字：52×14
- 字体：momozhuanji
- 字号：8
- 字重：600

适用：

- 当天没有照片但有有意义的文字内容
- 文字与线描插画共同表达当天内容

### 10.4 纯文字

类型 ID：`text_only`

固定规格：

- 文字框：52×62
- padding：2
- 字体：momozhuanji
- 字号：10
- 字重：600

适用：

- 心情记录
- 有意义的聊天内容
- 有意义的系统截图或纯文字截图

### 10.5 非日历格子比例图

类型 ID：`non_cell_ratio_image`

固定规格：

- 宽高：46×63
- 左 padding：9
- 右 padding：1
- 保留原画面比例

适用：

- 电影海报
- 游戏海报
- 专辑封面
- 需要保留窄幅构图的图片

### 10.6 多张异形抠图

类型 ID：`multi_irregular_cutout`

固定规格：

- 图片数量不超过 3
- 允许多个透明主体美观堆叠
- 遵循异形抠图安全区和极限区

适用：

- 同一日期重复场景中的不同物品
- 桌面上多个可分别展示的食物
- 多个主体分别抠出比保留背景更美观

### 10.7 圆形图片

类型 ID：`circle_image`

固定规格：

- 圆形：63×63
- 允许突破所属日期格
- 圆心必须位于所属日期格内
- 可以裁切以突出主体

适用：

- 穿搭局部
- 动物
- 主体适合圆形聚焦
- 局部画面特别出彩

### 10.8 椭圆图片加抠图

类型 ID：`oval_image_with_cutout`

固定规格：

- 椭圆主图：54×63
- 最多使用 2 张图片
- 总体范围遵循安全区和极限区

适用：

- 主要活动加次要物料
- 购物物品为主、票据为辅
- 主图适合椭圆裁切，辅助素材适合抠图

### 10.9 异形抠图加文字

类型 ID：`irregular_cutout_with_text`

固定规格：

- 字体：momozhuanji
- 字号：6
- 字重：600
- 文字与主体穿插排列
- 遵循安全区和极限区

适用：

- 清晰且具有明确意义的物品展示
- 短文字可以补充活动内容

文字不得遮挡人物脸部、宠物头部、商品主体或其他关键区域。

### 10.10 异形抠图

类型 ID：`irregular_cutout`

固定规格：

- 允许裁切突出主体
- 旋转绝对值不超过 10 度
- 遵循安全区和极限区

适用：

- 人物半身
- 玩偶
- 动物
- 卡片
- 手办
- 手拿物品展示
- 多个食物或物品可以整体抠图的场景

### 10.11 留白

类型 ID：`blank`

适用：

- 当天没有合格照片
- 没有足够有意义的文字
- 使用插画也会让画面过满
- 为整个月版面保留呼吸感更美观

## 11. 异形素材区域规则

异形抠图、多张抠图、抠图加文字和椭圆图加抠图使用两级范围：

| 区域 | 尺寸 | 规则 |
|---|---|---|
| 安全区域 | 72×80 | 所有主体应优先控制在该区域 |
| 极限区域 | 78×86 | 可以局部进入，但任何内容不得超过 |

额外要求：

- 主体视觉中心必须属于原日期。
- 不得遮挡其他日期数字。
- 不得进入相邻日期的主体保护区。
- 透明图片碰撞使用真实 alpha mask，不使用整张矩形边框。

## 12. 本地图片处理执行

本地执行器读取 `treatment_plan.json`，完成：

- 等比例完整图片。
- Cover 或 contain 裁切。
- 圆形和椭圆形遮罩。
- 单主体或多主体透明抠图。
- 图片旋转和缩放。
- 固定字体文字排版。
- 线描插画素材组合。
- 主素材与辅助素材组合。

执行器必须再次验证：

- 图片数量。
- 旋转角度。
- 处理类型是否存在。
- 固定尺寸是否被修改。
- 素材索引是否存在。
- 抠图是否有白边或阴影。
- 图片是否超出安全区或极限区。

## 13. 失败回退

建议回退关系：

```text
multi_irregular_cutout
→ irregular_cutout
→ proportional_full_image

oval_image_with_cutout
→ circle_image
→ proportional_full_image

irregular_cutout_with_text
→ irregular_cutout
→ proportional_full_image

irregular_cutout
→ circle_image
→ proportional_full_image

text_only / illustration_with_text
→ illustration_only
→ blank
```

触发回退的情况：

- 抠图边缘质量差。
- 人物或宠物主体被切断。
- 圆形或椭圆形裁切损失关键信息。
- 多素材无法在极限区域内完成布局。
- 文字遮挡主体。
- 原图分辨率不足。

## 14. 整月布局

当前阶段：

- 使用固定模板坐标。
- 按日期格、锚点、安全区、极限区和保护区排放素材。
- 本地程序执行碰撞和越界检查。

后续布局 AI 将读取：

```text
整月模板
+ 处理后的日期素材
+ 每个素材的真实轮廓和尺寸
+ 日期格安全区与保护区
+ 相邻日期占用状态
+ 参考完整预览
```

布局 AI 负责输出 1-3 个候选 `render_plan.json`，本地规则引擎负责校验和自动修复。

布局 AI 不得：

- 改变日期归属。
- 遮挡日期数字。
- 把主体视觉中心放进其他日期。
- 超出整月画布。
- 改变已经确定的图片处理方式。

## 15. 图层顺序

推荐渲染顺序：

```text
base
→ 完整图片和比例图片
→ 圆形、椭圆形图片
→ 异形抠图和多素材组合
→ 日期格文字
→ date
→ overlay_sticker_static
→ overlay_sticker_dynamic
```

静态装饰层完全跟随模板；动态装饰层根据当月内容选择图钉、爱心、相机/星星、唱片/音符或抽象贴纸。一处日期格最多 1–2 个视觉贴纸，且不得遮挡日期数字、主体面部和重要文字。

## 16. 自动质量检查

成图必须检查：

- 日期归属是否正确。
- 每日图片数量是否超过 3。
- 是否存在不支持的素材类型。
- 旋转是否超过 10 度。
- 日期数字是否被遮挡。
- 是否进入相邻日期主体区域。
- 是否超出极限区域或画布。
- 是否出现拉伸变形。
- 是否出现抠图白边、黑边或阴影。
- 是否存在重复使用同一照片。
- 处理失败后是否成功回退。
- 最终 PNG 是否可以正常打开。

硬性违规目标为 0。

## 18. 未来 API 自动化

以后切换 API 时保持不变：

- 选图流程。
- 图片理解结果。
- 产品规则。
- 10 种图片处理方式和留白。
- 结构化输出字段。
- 本地执行器。
- 安全区、极限区和 QA。

只替换调用方式：

```text
当前：会话内 GPT Vision 逐批判断
未来：API 批量调用并缓存结果
```

因此，当前 GPT Vision 阶段产生的规则命中结果、人工修改记录和最终处理方案，都应保留下来作为未来评测、提示词优化和模型训练数据。
