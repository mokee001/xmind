# AI 手帐日历本地小模型运行说明

## 推荐配置

当前默认使用：

```text
Ollama
+
Qwen3-VL 4B Instruct
```

本地视觉模型只负责图片理解与处理方式决策。照片导入、质量检测、去重、抠图、动态贴纸、布局约束、渲染和 QA 继续由本地代码完成。线描插画第一版优先使用本地素材库，不要求视觉模型生成图片。

## 安装与启动

先双击仓库根目录的 `安装API运行环境.command`，创建独立 `.venv` 并安装
项目依赖。然后安装并启动 Ollama：

```bash
brew install ollama
brew services start ollama
ollama pull qwen3-vl:4b-instruct
```

检查本地模型连接：

```bash
.venv/bin/python scripts/test_api.py
```

本地服务地址默认为：

```text
http://127.0.0.1:11434
```

## 项目配置

`calendar_engine/config.json`：

```json
{
  "decision_backend": "local_ollama",
  "decision_mode": "shadow",
  "api_enabled": false,
  "local_model_enabled": true,
  "local_ollama_decision_model": "qwen3-vl:4b-instruct",
  "local_ollama_base_url": "http://127.0.0.1:11434"
}
```

本地后端不读取 API Key。图片会编码后发送到本机回环地址，不离开设备。不要把模型名写成带 `cloud` 的版本。

## 单日测试

```bash
.venv/bin/python scripts/analyze_day.py /path/to/photo.jpg \
  --output outputs/local_day_decision.json
```

输出继续使用项目既有的 `ImageTreatmentDecision` Schema，并经过相同的本地硬规则校验。模型无法遵守 Schema 或触发日期、素材数量、文字长度、旋转等违规时，任务会失败，不会直接进入渲染。

## 4B 与 8B 切换

先用 4B 跑代表性案例。需要升级时：

```bash
ollama pull qwen3-vl:8b-instruct
```

然后将配置改为：

```json
{
  "local_ollama_decision_model": "qwen3-vl:8b-instruct"
}
```

模型切换不会改变 Prompt、规则、校准案例、处理计划和渲染器。

必须显式使用带 `-instruct` 的标签。`qwen3-vl:4b` 和 `qwen3-vl:8b`
短标签对应 Thinking 版本，容易先消耗大量推理 token，不适合此处要求稳定
JSON Schema 的批量决策任务。

## 验收标准

- 结构化 JSON 解析成功率：100%。
- 日期归属、素材数量和旋转硬违规：0。
- 处理方式可接受率：至少 80%。
- 抠图失败时能够回退完整图片。
- 与已确认的七月参考成图相比，不出现明显的连续方图和人物脸部误裁。

本地模型达到标准后，再把 `decision_mode` 从 `shadow` 调整为正式执行模式。未达标时保留 4B 结果用于对比，切换到 8B 重新评测。
