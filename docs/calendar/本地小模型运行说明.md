# AI 手帐日历本地小模型运行说明

## 推荐配置

当前默认使用：

```text
Ollama
+
Qwen3-VL 4B Instruct
```

本地视觉模型只负责图片理解与处理方式决策。照片导入、质量检测、去重、抠图、动态贴纸、布局约束、渲染和 QA 继续由本地代码完成。线描插画第一版优先使用本地素材库，不要求视觉模型生成图片。

## 一键安装与启动

推荐直接双击仓库根目录的 `安装本地模型.command`。它会检查 Homebrew、安装并
启动 Ollama、下载 `qwen3-vl:4b-instruct`、创建 `.venv`、安装 Python 依赖并
执行连接自检。模型权重保存在 Ollama 的本地存储中，不进入 Git 仓库；模型发行
约束记录在 `calendar_engine/local_model.lock.json`。

也可以手动安装：

```bash
brew install ollama
brew services start ollama
ollama pull qwen3-vl:4b-instruct
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

检查本地模型连接：

```bash
.venv/bin/python scripts/test_api.py
```

本地服务地址默认为：

```text
http://127.0.0.1:11434
```

## 项目配置

`calendar_engine/config.json`：

```json
{
  "decision_backend": "local_ollama",
  "decision_mode": "shadow",
  "api_enabled": false,
  "local_model_enabled": true,
  "local_ollama_decision_model": "qwen3-vl:4b-instruct",
  "local_ollama_base_url": "http://127.0.0.1:11434"
}
```

本地后端不读取 API Key。图片会编码后发送到本机回环地址，不离开设备。不要把模型名写成带 `cloud` 的版本。

## 单日测试

```bash
.venv/bin/python scripts/analyze_day.py /path/to/photo.jpg \
  --output outputs/local_day_decision.json
```

输出继续使用项目既有的 `ImageTreatmentDecision` Schema，并经过相同的本地硬规则校验。模型无法遵守 Schema 或触发日期、素材数量、文字长度、旋转等违规时，任务会失败，不会直接进入渲染。

## 整月统一入口

运行目录必须已经包含：

```text
prepared-run/
  manifest.json
  selection.json
  proxies/
```

双击 `运行本地日历工作流.command`，输入运行目录；也可以执行：

```bash
.venv/bin/python scripts/run_local_calendar_workflow.py \
  --run-dir /path/to/prepared-run \
  --resume
```

统一入口按固定顺序执行：

```text
输入与本地配置检查
  -> Ollama 连接检查
  -> 逐日结构化处理决策
  -> 整月艺术指导与处理计划
  -> 抠图/插画资产完整性检查
  -> 动态贴纸计划
  -> 日历渲染与 QA
  -> 图文报告
```

每次运行都会写入 `reports/local_workflow_report.json`，记录实际后端、模型名、
每个阶段状态、待补资产和最终输出路径。运行中断后增加 `--resume` 会复用已经
完成的逐日决策。

### 资产检查为什么会暂停

本地 Qwen3-VL 负责决定“该怎么处理”，不负责凭空生成透明抠图或线描插画。
如果处理计划引用以下尚不存在的资产，工作流以 `NEEDS_ASSETS` 停止：

- `assets/cutouts/dayXX.png`：由 macOS Vision 或后续抠图执行器生成。
- `assets/illustrations/dayXX.png`：从本地线描插画库选择，或由可选图片模型生成。

这是可恢复状态，不是错误。补齐报告列出的文件后重新运行即可继续装饰、渲染和
QA。这样不会在缺图时静默换成方形照片，破坏已经确认的处理效果。

## 当前封装边界

这套统一入口完整覆盖 `selection.json` 之后的链路。照片导入会生成
`manifest.json` 和代理图，但当前仓库尚未把已经确认的旧选图方法独立封装为
`selection.json` 生成器。因此目前不能只给一个全新相册目录就宣称全自动完成。

这不是模型限制，而是代码交付边界。下一步应把已及格的选图逻辑做成固定模块，
其输出契约保持为 `selection.json`，后续本地模型链路无需改动。

## 4B 与 8B 切换

先用 4B 跑代表性案例。需要升级时：

```bash
ollama pull qwen3-vl:8b-instruct
```

然后将配置改为：

```json
{
  "local_ollama_decision_model": "qwen3-vl:8b-instruct"
}
```

模型切换不会改变 Prompt、规则、校准案例、处理计划和渲染器。

必须显式使用带 `-instruct` 的标签。`qwen3-vl:4b` 和 `qwen3-vl:8b`
短标签对应 Thinking 版本，容易先消耗大量推理 token，不适合此处要求稳定
JSON Schema 的批量决策任务。

## 验收标准

- 结构化 JSON 解析成功率：100%。
- 日期归属、素材数量和旋转硬违规：0。
- 处理方式可接受率：至少 80%。
- 抠图失败时能够回退完整图片。
- 与已确认的七月参考成图相比，不出现明显的连续方图和人物脸部误裁。

本地模型达到标准后，再把 `decision_mode` 从 `shadow` 调整为正式执行模式。未达标时保留 4B 结果用于对比，切换到 8B 重新评测。

## Git 交付内容

进入分支：代码、Prompt、产品规则、校准案例、Pydantic Schema、Figma 位图模板、
动态贴纸种子库、模型锁文件、安装入口、统一运行入口和测试。

不进入分支：Ollama 模型权重、真实用户照片、代理图、运行报告、API Key、Figma
Token、个人绝对路径和 `.venv`。同事克隆后首次运行安装入口，下载同名模型即可。
