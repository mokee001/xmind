# 内容偏好与自动上屏 V2 草案

状态：产品与工程方案，尚未改变 V1 筛选规则或实现以下新增功能。算法基准为 Git 标签 `recollections-rules-v1.0.0`。

## 用户控制什么

用户决定素材来源、哪些人/内容不能出现、哪些内容更想看；系统负责从这些边界内选择回忆、照片、布局和更新节奏。模板作为后台排版资源，不要求用户理解或挑选模板。

偏好区分硬约束与排序倾向。硬约束不因素材不足、节日推荐、惊喜内容或模板填充而放宽。软偏好允许系统保留多样性，避免长时间只重复一种内容。

| 维度 | 建议交互 | 优先级 |
| --- | --- | --- |
| 人物 | 自动分组后确认身份；每人可设正常展示、多展示、不展示 | 首期 |
| 内容主题 | 旅行、宠物、美食、自然、舞台等；正常、多展示、不展示 | 首期 |
| 素材来源 | 选择授权相簿，明确可用于上屏的范围 | 首期 |
| 时间倾向 | 最近生活、过往回忆、均衡；按内容调整，非限定照片年份 | 后续 |
| 某段回忆 | 单张照片、一次活动、日期范围或旅行不再上屏，可撤回 | 后续 |
| 发现旧照片 | 保守、适中、更多变化；只在允许范围内调节新鲜度 | 后续 |
| 宠物身份 | 在有独立识别与确认能力后按具体宠物选择；首期只做宠物主题 | 后续 |
| 屏幕差异 | 每块屏幕继承偏好，明确覆盖项与作用范围 | 后续 |
| 呈现与更新 | 系统自动选择，后续可选简洁/丰富及更新频率；不暴露模板编号 | 后续 |

首期偏好页面只保留「展示谁」「想看什么」「照片来自哪里」，其他使用合理默认值；不要把所有维度一次性变成筛选表单。

## 人物偏好的确定语义

- 稳定的 `person_id` 与识别人脸簇分离；重新分析或新增照片不会更换用户偏好的对象。
- 未确认时用人脸缩略图和中性名称展示，不推断姓名、亲属或朋友关系。允许确认、改名、合并和拆分错误分组；排除冲突未解决前保守处理。
- 「多展示 A」提高包含 A 的照片与相关回忆的排序，不意味着其他人被禁止。
- 「不展示 B」默认排除所有识别到 B 的照片，包括 A 与 B 的合照；不是只隐藏 B 的人物相册。不使用自动裁掉 B 作为首期替代方案。
- 「只展示指定人物」若实现，应单独说明它排除其他人物主体；无人物照片是否可用由主题选择决定，不能把“多展示”悄悄解释为白名单。
- 人脸识别失败或身份不确定要保留状态，不能把缺失标签当作已确认不含被排除人物。严格排除场景中不确定的相关照片暂不自动上屏，并提供纠正入口；模型不能保证完全不漏检。
- 选择多个允许人物/主题通常为并集；禁止条件命中任一即排除。明确的组合意图（例如与 A 一起旅行）才采用交集。

## 后台链路

授权照片与特征 → 稳定人物映射 → 硬排除 → V1 候选聚合 → 偏好/质量/多样性选片 → 自动选布局 → 渲染质量检查 → 待上屏队列 → 发布前复核 → 设备确认。

人物分类是照片索引；精选集是组织照片的叙事候选。人物偏好作用到所有精选集成员。排除后重新挑选封面和成员，必要时取消不再满足门槛的回忆；不能只删掉人物类别卡片。

精选集可保留 12～24 张作为候选素材；一次屏幕画面的张数由屏幕尺寸、内容完整性与可读性决定，不要求整册照片一次塞入。

自动排版检查人物是否被裁切、主体是否清晰、照片数量与留白是否合适、字体可读性、目标屏幕的颜色/对比度表现。没有合格新内容时保留仍符合当前偏好的旧画面；旧画面也违反新约束时清除/替换为中性画面，设备离线时显示待同步状态，不能宣称已撤下。

所有生成入口统一读取同一偏好策略：普通精选、人物回忆、惊喜老照片、宠物专用流程、日历内容及手动生成。偏好带版本号，变更后使受影响的待发布结果失效，发布前核对版本，防止旧队列重新上屏。

## 当前代码接入点

- `selection_lab/recollection_feed.py`：V1 回忆候选与选片，继续保留为基准。
- `selection_lab/stories.py`：已有 Ente 人脸候选；当前人物标识来自簇内人脸列表的摘要，不能直接作为跨重跑的稳定偏好 ID。
- `backend/faces.py`：生产侧另有人脸处理路径，需建立统一的人物映射，不能混用不同模型的向量或临时人物序号。
- `photo-wall-app/App.js`：已有内容偏好入口及预览占位人物数据；真实人物映射、偏好存储和执行语义仍需接通。当前多选逻辑不足以表达“多展示”和“只展示”的区别。
- `backend/server.py`：现有通用生成路径已有排除过滤，但正向筛选无匹配时可回退全部；硬白名单不得沿用这种回退。当前模板先决定槽位，新流程应先定内容，再选适合布局。

## 建议验收

首期验证人物确认与纠错、增量照片后的身份稳定、合照排除优先、未知身份处理、空候选、跨主题人物排除、偏好改变导致旧队列失效，以及所有生成入口一致执行。用新图库验证泛化，不把原 8 个精选集当作唯一正确输出。

质量与惊喜通过持续反馈评估：收藏、主动保留、跳过、不再展示及原因。不能把没有点击视为喜欢，也不能为提高更新率放松硬约束和质量门槛。
