## 为什么 1.3.14（37）仍不能顺畅恢复

上一版补充了请求时限、错误提示和绑定保护，阻止未确认删除时直接抹掉本机会话，但仍有以下实际缺口：

- **检查连接缺少可见反馈。** 手动检查可能遇上进行中的自动轮询，旧逻辑直接返回；日历重试在历史仍加载时也会忽略点击。原生模拟器还确认日历自动滚到当前月份后，上方提示可能不在可见区域。请求有超时不等于用户能看到点击结果。
- **原生弹层切换没有等待退出。** 设备管理、添加设备和蓝牙设置使用不同的 React Native `Modal`；同一帧关闭一个并打开另一个没有等待 iOS 原生退出完成。浏览器 Demo 的弹层测试不能证明这个原生转场正确。
- **生产主服务确实缺少重新配网路由。** 只读核对中，8000 主服务的 OpenAPI 含删除与历史接口，但不含 `reprovision`；8001 为选片服务，同样不含该路由。App 先等待云端重新配网成功才打开蓝牙设置，使恢复入口依赖了尚未部署的能力。
- **旧 DELETE 没有可验证的重试回执。** 云端完成删除但手机未收到响应时，再次请求可能返回 401。401 同时可能意味着权限不匹配，不能把它、404 或空设备列表当成已经解绑；因此旧 App 会一直保留本机绑定。

生产证据见 `outputs/offline-recovery-20261013/reconnect-review/production-evidence.json` 和 `preflight.json`。16:47 的检查中，本机两个 API 健康检查为 200，服务器访问公网域名的一次请求在 5 秒超时；照片墙最后心跳为 16:01:32，存储中的 `online` 字符串已不能表示当时在线。访问日志只有请求完成记录，不能还原手机故障时的网络路径，也不能从日志缺少记录推断请求从未到达。

## App 的恢复行为

### 检查连接

检查立即显示“正在检查”，并在最多 8 秒后给出结果。已有自动读取时，手动检查复用并等待同一请求，不静默丢弃点击；日历加载期间也允许发起检查。结果显示在固定顶部及设备管理中，避免只放在滚出屏幕的日历内容或页面底部。

结果区分服务不可达、设备权限待确认、真实心跳过期和设备报告异常。手机访问服务失败不能被解释为照片墙 Wi-Fi 断开。服务成功读取到新心跳才支持“照片墙在线”的结论。

### 云端删除与仅从本机移除

优先向云端请求删除。查找缺失的绑定信息与发送 DELETE 合计设置 10 秒预算，覆盖响应体读取；超时后不继续发送迟到的下一步请求。只有设备 ID、绑定代次和删除请求 ID 均匹配的明确成功回执，才清除本机绑定。

删除未确认时，保留设备并显示“仅从此手机移除并重新连接”。用户再次确认后：

1. 先将当前设备授权、未完成上屏意图及对应可用偏好保存在此手机的独立 SecureStore 恢复记录中。
2. 保存成功后才移除可见设备；保存失败保留原设备与原权限。
3. 不请求云解绑，不清除屏幕 Wi-Fi，不安排后台自动重放 DELETE。
4. 自动账户同步不能把这个本机移除的设备立即加回来；用户显式重新连接成功后才清理恢复记录。

本机移除与云端解绑是不同操作。界面明确说明该差异，不能用本机列表为空宣称云端绑定已解除。操作其他设备时也不把当前设备的偏好复制过去。

### 本机移除后重新连接原设备

本机移除后进入添加页，先显示“重新连接已移除设备”的明确目标列表，同时保留“添加其他设备”。列表只读取本机 SecureStore：打开页面、读取列表或 App 重启都不会自动发送云端请求，也不会把设备恢复到正式列表。

用户点选某台原设备后，App 再次检查保存的账户、设备 ID、绑定代次及该设备尚未在正式列表中，保存本次恢复页面状态，随后打开蓝牙设置并请求云端唤起**这一台**在线屏幕。唤起等待、失败或超时都有可见反馈；不能只打开通用 BLE 搜索而让仍在线、不广播的原设备永远搜不到。取得蓝牙新凭据后仍使用同一持久化操作授权，不因本机移除而绕过服务端权限。

关闭恢复设置会返回添加页，只清理匹配的待恢复页面状态，保留设备授权、偏好和同次云端操作。明确取消后重启不强开恢复设置；原设备仍可从“重新连接已移除设备”入口选择。如果配网过程中 App 被终止，重启仅打开目标选择页，不自动唤起任何设备。新用户欢迎页、连接页及未连接状态的管理入口均能到达该选择页；添加其他 ESP32 使用独立通用流程。

恢复目标与仍在列表中的“重新配网”会话分开。新蓝牙设备的 ID、原授权和绑定代次必须与显式目标一致；只有实际连接结果成功保存后，才恢复正式列表并清理对应本机恢复记录。SecureStore 提交阶段也校验原恢复授权，不能让迟到结果覆盖同账号同设备的新绑定。若云端其实已经删除设备而手机丢失回执，401/403 后仍保留凭实体蓝牙证明尝试正常认领的路径，但不会继承旧绑定的上屏意图或发布版本。

### 重新连接与权限恢复

“重新配网”立即打开蓝牙设置，同时显示“正在请求照片墙进入配网模式”。39 保留让在线屏幕无损进入配网的云端指令，并用同次操作记录保护后续蓝牙授权。请求失败或超时会明确显示尚未确认，蓝牙搜索和返回入口仍可使用，不让云端等待挡住整个页面。

现有 0.3.7-e1002.1 固件中，已正常联网的屏幕不常驻 BLE，云端重新配网指令可以保留设备凭据并重启进入配网。因此不能用“直接搜索蓝牙”替代在线屏幕的正常重配网。设备离线且不广播时，App 不能唤醒它；应先恢复屏幕联网或按经核实的硬件恢复流程处理。恢复出厂会清除设备凭据，不能描述为无损换网。本轮不编造运行时绿键配网能力或未经验证的长按秒数。

选中与恢复记录相同的设备、取得新的蓝牙配网凭据后，优先使用原授权进行重新配网。若原绑定已不存在而旧授权返回 401/403，只能凭实体蓝牙凭据尝试正常的服务端认领流程；仍受服务器鉴权，不能据此解除他人的绑定。服务拒绝时保留明确错误，不伪装恢复成功。

38 号构建曾移除无配网凭据的预先请求以避免迟到竞态；继续核对固件后发现这会丢失正常在线换网入口，因此该构建上传后已停用。39 已实现两阶段配网，配套服务已部署；实际 App 与同版 FastAPI 接口串联验证通过：

1. 第一次读取当前公开绑定与 `recovery_generation`，将 `operation_id`、绑定和原始代次写入 SecureStore，再发送 `enter_setup`，请求在线屏幕进入配网。
2. 取得同一设备的新蓝牙配网凭据后，使用**同一操作 ID 与同一原始代次**发送 `authorize`。不为第二阶段自行刷新代次或新建操作。
3. 丢响应、超时、关闭页面及 App 重启后保留原操作记录。仍已绑定设备的未完成配网页提供继续请求入口；本机已移除设备先回目标选择页，用户明确选择后安全重试原操作。不静默发起新一轮。
4. 服务器确认该操作已被替代、凭据不同或过期时，显示冲突；只有用户明确点“重新开始本次配网”才读取新代次创建新操作。该选择只消费一次，之后 Wi-Fi 失败的普通重试继续复用已经保存的操作。
5. 同操作的迟到 `enter_setup` 不能清掉已登记的蓝牙凭据，也不能重启已完成流程。实际 bootstrap 匹配当前凭据后标记完成；裸设备状态回执不能清除新凭据或把完成状态回退。App 收到真实配网成功并保存本机会话后，才清理对应本地操作记录。

唤起与授权的每次协调请求仍有 10 秒时限，覆盖读取元数据、持久化意图和 HTTP 响应；到期或取消后的迟到结果不能继续发送下一步。新绑定、管理操作代次和蓝牙流程代次共同阻止旧回调影响新的连接。

同一绑定恢复时保留首次准备意图和已发布墙版本，继续按真实设备回执核对，不重复发布。服务器返回新绑定代次时，不把旧绑定的意图或上屏版本带过去。相同设备重新认领到新账户时可恢复此手机保存的偏好；空的云端偏好列表不抹掉该恢复偏好，也不冒称它已经同步到云端。

### 原生转场与迟到响应

设备管理 → 添加设备 → 蓝牙设置，以及重新配网返回管理，均等待实际 `onDismiss` 后再呈现下一层。蓝牙设置和附近设备提示在退出动画期间保留原生呈现对象，确保退出回调不会因提前卸载而丢失。

操作起点和 SecureStore 队列真正提交时均核对目标账户、设备及绑定代次。保护也覆盖非当前设备：即使首页当前设备没有变化，同账号同设备的新绑定也不能被旧删除回执清掉。旧异步读取、家庭同步和首次准备保存不能恢复已移除的旧会话。
