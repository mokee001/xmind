# 第一层精选与第二层展示偏好

用户澄清：增加人物识别是为了偏好选择，不是新增人物相簿。版本 `recollections-preferences-v1`。

入口：<http://127.0.0.1:8766/recollections-v2>，点击“展示偏好”。

## 两层职责

1. **后台精选**：保持确认过的 V1 主题／旅程、质量、去重、选片权重和 12～24 张规则。为保留策略，第一层内部继续使用原 V1 的人物证据，新增 Immich 身份不参与第一层排序、聚合或去重。本批重新生成 8 个候选集，135 张唯一精选照片，所有候选集的成员和顺序与 V1 一致。
2. **展示范围**：独立读取完整 Immich 索引，偏好列表仅显示第一层精选中有匹配照片的人物。人工确认合并前为 8 个候选，合并后为 4 个偏好选项，头像也取自第一层精选照片。用户可展示全部精选，或多选人物仅展示匹配任意一人的精选照片。零匹配人物不显示、不可提交；269 个未归组脸框不当作独立身份选项。

严格关系：`展示照片 = 第一层已入选照片 ∩ 人物偏好匹配照片`。人物偏好不召回未入选原图，不更改第一层成员，也不再次执行成册最低张数。多组重叠照片在展示层只出现一次。人物名为自动候选编号，没有识别或猜测姓名。

本批用户确认人物 1、2、15、24、37 是同一人。偏好中合并为人物 1，共匹配 17 张唯一精选照片；其余候选分别匹配 9、1、1 张。此数据来自当前快照，不是固定配额。

## 保存与安全边界

第一层结果、偏好和验证记录独立存于数据集的 `recollections-preferences/`。原 V1 与上一轮人物相簿 V2 快照均保留，不改写旧偏好。此轮没有重新推理 Immich，继续校验同批真实完整导出。

预览接口只计算数量、不写偏好。保存接口校验同源请求令牌、当前快照、人物索引版本和人物 ID。换图库不挪用旧选择；人物识别版本变化时，限制模式需要重新确认，不自动放宽为全部展示。历史偏好里的零匹配人物仅在读取时忽略，不改写保存记录；剩余选择为空仍保持零张。未选择任何人物的限制模式显示零张，切回“全部精选”才恢复全部范围。

接口：

- `GET /api/recollections-v2`：第一层候选、人物索引、保存的偏好与 `display_photo_ids`。
- `POST /api/display-preferences-preview`：不保存，返回预计展示 ID 与数量。
- `POST /api/display-preferences`：保存当前展示范围。
- `GET /person-preview/{personId}`：按已验证的人脸框生成本地头像，去除 EXIF，不修改原图。

保存／预览请求字段为 `snapshot_id`、`identity_revision`、`mode`（`all` 或 `include`）、`person_confirmation_revision` 与 `person_ids`。消费展示结果的后续终端应使用 `display_photo_ids`，不应将返回的完整图片字典当成允许展示范围；完整字典供偏好头像及后台诊断使用。

自动测试覆盖交集、多选并集、空选择、零匹配、小于成册门槛仍可展示、第一层不变、预览不保存、保存重读、图库／身份版本／快照隔离和 HTTP 令牌。界面检查真实头像、单选多选及匹配计数。

## 人工确认与高频展示（confirmed-frequent-people-v3）

人工确认记录保存在当前数据集的 `person-confirmations.json`，绑定图库和原始识别版本。只合并用户明确确认的组，不根据头像猜测身份；保留原始 Immich 索引供核对。原先选择任一别名都会映射到合并后的选项，原偏好文件无需覆盖。新识别版本不能直接复用旧合并，过期页面提交也会被拒绝。

偏好按第一层中出现的唯一照片数降序排序，同数按稳定 ID 排序；多张人脸、跨候选集重复照片不重复计数。默认展示最多 6 人，超过时提供查看全部／收起，已选人物文字摘要始终保留。少于 6 人不补位，也不推断亲属关系。选项与排序不依赖当前第二层选择。

本次未重新生成第一层或运行识别。验证原始索引、第一层快照及已保存偏好字节不变；新增人工确认与展示逻辑的测试覆盖合并去重、旧别名映射、精选交集、稳定频率排序和确认版本隔离。
