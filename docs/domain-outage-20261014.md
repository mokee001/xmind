# 域名过期导致的设备恢复中断 · 2026-10-14

## 本次已确认的原因

用户在 App 1.3.15（39）重新连接原设备时，界面同时停在请求配网和蓝牙搜索。
本次读取 PHOTOWALL-B4DC 串口，确认屏幕连接 Wi-Fi 成功，但云端 bootstrap 的
TLS 连接失败（HTTP -1）。不能据此认为 Wi-Fi 密码错误或蓝牙硬件损坏。

14:09–14:14（上海）分别从 Mac 和生产服务器核对：

- `.cn` 父区把 `mokeedesign.cn` 委派给 `expirens3/4.hichina.com`。
- 过期权威 DNS 把 `api.mokeedesign.cn` 指向 `expired.hichina.com`；返回的三个
  IP 均无法建立服务连接。
- 保持正常 TLS 证书校验，仅用 `curl --resolve` 指向生产 IP `8.217.158.5`，
  两端 `/healthz` 均返回 200。服务进程、端口及证书正常。
- 阿里云登录后的域名列表明确显示“急需续费，已过期 2 天”，到期日为
  2026-10-12 13:00:12。公开 WHOIS 的 2027 日期没有证明用户已经续费。
- 原来使用的是 Cloudflare 的 `natasha.ns.cloudflare.com` 和
  `simon.ns.cloudflare.com`；直接查询两者，API 的 A 记录仍为正确生产 IP。
  因此没有在 AliDNS 新增记录，也没有手动更换原 NS。

这些证据解释本次手机访问服务、云端设备操作及屏幕心跳同时失败。
它们不能反推之前所有上传、照片格式、识别范围错误都出自 DNS。

## 续费与恢复验收

用户在已打开的阿里云页面自行完成一年 42 元续费。约 14:15:26 支付页显示成功，
刷新控制台后域名为“正常”，有效期为 2027-10-12 13:00:12。
助手没有代为勾选协议、提交付款或开启自动续费。

首次复验（14:16:30–32）：注册局已恢复原 Cloudflare 委派，但部分递归缓存仍指向
过期停放地址；普通域名访问尚未成功，实体屏幕尚无新心跳。续费成功与链路恢复
分开记录，不能以 `--resolve` 对照测试代替正常解析的实际请求。

后续验收需分别记录普通域名 HTTPS、目标屏幕真实心跳、手机重新连接结果。
当时的证据位于 `outputs/ble-recovery-20261014/`，包括
`network-root-cause.md`、`post-renew-1/` 和脱敏串口日志。

## App 中另外修复的等待缺口

代码审查及合成复现确认了两处问题，但没有手机日志证明它们是本次故障的触发点：

1. 重新配网的本机恢复记录读取原本位于 10 秒请求时限之外。现将读取与云端请求
   统一纳入 10 秒，取消或超时后迟到的本机读取不能再发出 HTTP 请求。
2. 蓝牙扫描的等待计时原本在原生启动完成后才开始。现从操作入口开始，原生准备
   最多 20 秒；已经启动的扫描在 UI 结束等待后继续接收广播，直到选择、关闭或重搜。
   已验证 30 秒和 60 秒才出现的广播仍能进入设备列表，不把正常延迟当作失败。

原有 139 项加新增 9 项回归，共 148 项通过；独立审查重跑相关 50 项通过。
测试使用实际 App 函数和 BLE 适配代码配合合成原生响应，不代表实体 iPhone BLE 验收。
相关报告在 `outputs/ble-discovery-20261014/`。此记录时尚未发布新的 App 安装包。

## 现有固件的恢复边界

实际恢复用版本为 `0.3.7-e1002.1`。启动时 Wi-Fi 连接失败会进入 BLE 配网；
运行中掉 Wi-Fi，或者 Wi-Fi 已连接但云端不可达时，不会自动开启 BLE。
正常在线换网仍依赖云指令。因此 DNS 停用会阻断远程唤起，手机扫描不能使未广播的
屏幕出现。当前绿键开机长按会清配置，不能描述为无损重连操作。

本轮未刷固件、清 NVS、恢复出厂、变更照片/识别策略或重新上传照片。
固件取证与尚未实施的无损恢复设计在归档 `firmware-audit.md` 中。
