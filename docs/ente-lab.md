# Ente 本机实跑：使用、边界和调整规则

更新：2026-09-08 已支持独立数据集路径及默认活动数据集，加入共享相簿后共 447 张；最新一轮自然回忆 2 组。以下“本次真实结果”的 132 张 / 0 组是最初基线，仍保留，不是最新合并结果。详见 [共享相簿导入记录](shared-album-import-2026-09-08.md)。

## 直接使用

2026-09-08 最新展示要求：Ente 入口仅展示“原版回忆相册”，已移除界面上的主题匹配和人物检测汇总入口。活动数据集 447 张，本轮原版自然输出“翻过山丘”8 张、“Last month”10 张，共 18 张，保留导出的成员和顺序。结果用本项目查看器展示，不代表已经验证完整 Ente App 的原生界面与全部服务层行为。

此前的“人物相册”曾将所有检测到人脸的照片合并展示，既不是同一人物聚合，也不是原版最终精选；不限张数的主题匹配同样只是识别诊断。两者已撤出正常展示，缓存中的 `ente_people`、`ente_recognition` 只保留作诊断，不能冒充原版自然回忆。

打开 `http://127.0.0.1:8766/#ente`。首页保留“当前方案”和“Ente 原版结果”两个独立入口。“本机重跑 Ente”会复用识别索引，重新运行回忆计算并保存自然结果、调试候选两份快照。只接受当前固定数据集，不接受任意命令或当前方案权重。

服务未启动时，在项目根目录运行 `python3 tools/selection_lab.py --port 8766`，或使用原来的启动实验台文件。手动计算命令是 `python3 tools/run_ente_lab.py`。不要同时从多个终端启动计算；网页防止同一进程内的重复启动。

页面重跑失败时保留上次成功快照，并显示失败状态。没有 Ente 结果时绝不用当前方案冒充。切回“当前方案”即可继续使用原来的精选集，未修改线上策略、手机 App 或原照片。

## 本次真实结果（2026-09-07）

同一批 132 张七月样本：132 个图片向量、87 次人脸检测、81 个人脸分组，最大组 2 张脸；7 张照片有 GPS 并建立城市索引。人脸检测次数和分组数不等于真实人数。

Smart Memories 计算的自然结果 **0 组**，调试展开也 **0 组**。这不是模拟数据，也不能据此断言 Ente 产品没有回忆功能。只说明这个固定版本、这批样本、这些元数据和初始状态下，本次回放没有成册。

核查依据直接来自本次向量和固定源码条件：

- 48 个原版内容主题中，超过相似度 0.225 的最多为“美食盛宴”和“城市落日余晖”，各 6 张；“毛茸茸的伙伴”4 张。原版 `ClipMemoriesCalculator` 至少需要 10 个匹配候选才开始成组。相似度不是置信概率，候选是否识别正确仍需人工评估。
- 最大人脸组只有 2 张脸，未达到未命名人物回忆至少 5 张非大合影、至少 4 个非连续日期等条件。
- 当前历史、近期、日历回忆候选窗口均为 0。样本仅七月，不能当成完整多年相册测试“往年今日”等能力。
- 每张照片的 ID 与图片向量 ID 已在 Dart 测试中核对，向量维度及归一化已验证；没有用现有 Vision/Immich 向量顶替。回忆计算测试成功不等于模型识别准确率经过验收。

因此当前不能交付一个声称“Ente 原版生成”的漂亮相册集。下一轮应保留这个原版基线，再单独实验“Ente 识别 + 本项目成册规则”，不能偷偷改原版门槛后仍叫原版结果。

## 实际运行了哪些代码

- Ente 仓库固定 `7dc875ce12c781733b289cd27bbb0f3a99675aa2`，版本 `1.3.64+2158`。
- 原版 Rust `ente-ml` 的图片预处理、YOLOv5-face、MobileFaceNet、MobileCLIP-S2 图像与量化文本推理；本次 132 张均报告使用 Core ML。
- 原版 Dart `runLinearClustering`：推荐距离 0.24、保守距离 0.16、动态阈值开启。
- 原版 `SmartMemoriesService._allMemoriesCalculations`：本地 Gallery 上下文、ML 开启、未命名人物回忆开启、空账号/命名/已看历史；自然与 `debugSurfaceAll` 分开运行。自然输出按本轮时间范围过滤。
- 原版 `ente-location` 城市和城市区域索引；无 GPS 的照片没有编造位置。
- 中文标题来自 Ente 自带本地化；新用户无已看记录，封面使用首项，保留原始成员顺序。

适配器只做本地输入映射、原版私有入口桥接、结果导出和只读诊断。受保护的识别/选片源码发生修改时，运行器拒绝标记为原版。

这是 **macOS 源码回放，不是完整 Ente 手机 App**。没有运行相册数据库导入、账号与人物命名、持续后台扫描、完整 UI 展示和历史轮换持久化。服务层 `_finalizeMemoriesResult` 的数据库依赖简单回忆兜底未运行；本批该兜底所用历史日期候选窗口也为空。不能推断其他数据下完整 App 与此结果完全相同。

## 数据规则

1. 为与现有实验台使用同一时间基准，日期来自文件名 `2026-07-DD`，仅日精度；统一中午是占位编码，不是精确拍摄时间。不人为制造分钟间隔让原版通过时间去重。
2. 原 EXIF 的日期不完整且与文件名冲突，不悄悄混用；以后换原始相册资源时应统一调整两个引擎的日期策略并生成新数据集签名。
3. Ente 原版基线不套用本项目照片-only、画质、截图复核或 Top N 规则。若未来产出含截图，不能称为通过了产品最终审核。本次 0 组，没有向最终相册输出截图。
4. 不调整阈值以保证“好看”。“原版”和“Ente + 自有策略”必须用不同引擎名、快照和来源说明。
5. 原版有随机主题轮换及候选抽样。保存快照是看回同一结果；重跑不保证逐张相同，调试候选也不等于自然首页。

这些目录受现有 `.gitignore` 排除。首次准备只下载源码、工具链与模型；没有上传照片或特征。Rust 入口没有网络请求逻辑，Dart 测试禁止创建 HTTP 客户端；这不等于系统级网络沙箱。向量、GPS 和文件名仍是敏感本地数据，不应对外分享运行目录。JSON 缓存及日志设置为仅当前用户可读写，不修改 shell 配置。

索引缓存键包含照片集签名、源码版本、模型摘要和 Rust 适配器摘要。样本或模型变化会失效；只调整回忆层时复用识别结果。模型首次编译和下载可能较慢，不应作为用户手机首次扫描时间的估计。

本机一次通过网页接口的热缓存重跑约 8 秒完成（包含模型校验、Flutter 测试启动及快照保存）；这是当前机器的一次观测，不是手机性能承诺。

## 环境重建与开发

当前机器的环境已准备完成，不需要每次重复安装。换机器时需要 macOS Apple Silicon、Xcode 命令行开发环境、项目 Python 依赖、以上固定 Flutter/Rust 版本，以及固定 Ente checkout。所有工具链放在 `engines` 下，`PUB_CACHE`、`CARGO_HOME`、`RUSTUP_HOME` 使用绝对路径，`PATH` 加入本目录 Flutter/Cargo bin。避免用包含 `..` 的同义缓存路径造成依赖重复下载。

准备顺序：

1. 在固定 Ente `mobile` 工作区执行 `flutter pub get --enforce-lockfile`。
2. 在固定 Ente `rust` 工作区执行 `cargo build -p codegen`、`cargo codegen frb photos`，Rust 工具链需含 `rustfmt`。使用上游生成器，不手工伪造绑定文件。
3. 在 `mobile/packages/strings` 执行 `flutter gen-l10n`。
4. 在本项目根执行 `python3 tools/prepare_ente_lab.py`，按固定官方资产清单下载并校验模型、构建本地 Rust 入口。
5. 执行 `python3 tools/run_ente_lab.py`。网页检查模型配置、Rust 可执行文件、Dart 依赖、生成绑定与本地化文件齐全后开放重跑。

升级上游时需同时审核 `prepare_ente_lab.py` 的版本/资产、`run_ente_lab.py` 的提示词枚举数量/来源，以及 Dart 数据结构与私有计算入口。不能只换提交号沿用旧模型和接口就宣称验证完成。商业分发或嵌入产品前，另行评估 Ente AGPL 及模型/工具链各自许可；当前只是本地实验，不代表已完成授权合规评估。
