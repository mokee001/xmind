# 首次准备的人物偏好恢复入口

## 真实原因

用户 21:20 截图显示“人物识别分组已变化或尚未完成，请重新确认人物偏好；未忽略原有范围”。21:26:22 的只读核对显示：

- 119 张输入的正式分析已于 21:11:14 完成，第一层精选为 16 张、1 册。
- 原始识别及人物索引有 49 个分组，但当前第一层精选的 `people` 列表、照片的 `person_*` 标签均为空。这不表示图库完全没人，也不证明身份永久失效。
- 21:19:44–21:22:59 共 11 次就绪检查，没有新的生成、上传或投送。结合用户截图与代码，人物范围检查在准备阶段阻断，重复按钮会继续发送原偏好。服务器未记录这些请求的响应体，不能据此断言手机当时保存的具体人物或数量。
- 屏幕仍在线。此次恢复不涉及 Wi-Fi、固件或设备绑定。

正式筛选规则要求人物范围只作用于第一层已入选照片。不能为了消除报错静默丢弃偏好、从原图库补图、展示不属于当前范围的人物，或把没有匹配说成还在识别。

历史本机偏好使用全局加密缓存键；当生产设备偏好接口尚未部署时，App 保留本机版本。未解析的人物约束也会保留并提交，因此存在旧选择被继续带入的路径。本次没有读取手机私有缓存，不能断言具体是哪一组或哪次设置带入。

## 恢复路径

人物范围错误 → **调整人物偏好** → 只读刷新当前可选结果 → 明确处理待确认的旧选择 → **保存并继续准备**。

- 恢复入口复用现有偏好页，进入即为管理草稿，不增加首次设置必填步骤。
- 当前候选读取失败时提供重新读取，不把加载失败当作人物消失。
- 原选择保留在草稿，缺少可靠姓名/头像时使用中性标签，不猜测身份。用户明确取消旧项才修改草稿；保存才应用。
- 本次精选没有人物时明确说明这一点；取消所有人物约束后，告知按自然安排继续，不静默放宽范围。
- 返回保留原失败页、连接和已保存偏好；保存失败保留草稿。同值保存也处理恢复，但不能带着未处理的旧约束盲目再次生成。
- 保存后使用新快照和偏好版本恢复首次任务，核对设备绑定代次；保留已发送版本与真实回执对账，不能重复投送。
