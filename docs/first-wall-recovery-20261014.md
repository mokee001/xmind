# 首次准备等待与恢复修复 · 1.3.17（41）

用户于 2026-10-14 明确授权将首次准备问题一并修复、合入并直接打包发布，不再逐步确认。此修复不包含尚未确认迁移的四模板自动选择 Demo，也不改变固件。

## 原因与处理

本次实测屏幕在线，但生成被已有 6 项人物范围约束挡在 `people_pending`。旧 App 在等待正式人物结果时仍反复请求生成，并按重试次数再次补传，24 次后报错。服务器在完整结果没有合格相册时回退到有效初筛快照，却仅按快照的 `provisional` 类型判断仍在处理，造成已完成和未完成混淆。

删除并重新认领会建立新的账户图库范围；旧人物 ID 不应被随意映射到新人物，也不能为上屏而清空选择。此次没有跨账户复制照片、合并人物或修改已有偏好。当前版本确认人物范围失配时，使用已有偏好恢复入口，由用户明确保存新的选择。

- readiness 保留原合同，增加 `generate / wait / upload / review`、实际处理阶段、当前输入是否完成、是否需恢复任务。查询本身不启动任务。
- App 仅收到明确 `upload` 才进行有上限的补传。人物分析、排队及暂时网络错误期间只读等待；就绪后才生成，竞争导致的 409 回到状态查询。
- 初批保留最多 16 张的原有边界，最多四批；人物任务等待不再任意启动下一批。全局十分钟截止保留，并区分分析未完成与已发送但未确认，不再统一归咎网络。
- 服务重启后可通过原 `/session` 恢复一次；后台失败冷却结束后再次尝试可恢复，避免每次点击都返回相同终止状态。
- 只有当前图库修订成功完成、来源仍完整时，空正式结果才可证明本次识别已结束；旧结果、失败结果、排队状态均不能冒充当前完成。低于固定成册最低 12 张的输入不据此宣告人物失效。
- 保留自然安排从真实有效初筛候选快速生成首墙的既有策略，不改变模型、评分、主题、聚合、去重或 12～24 张正式成册基准。
- 发送前持久化意图、恢复时先对账、真实设备回执后才写日历等既有保护保持不变。
