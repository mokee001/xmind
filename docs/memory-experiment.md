## 分组变化

新活动组仅使用原规则认可的时间戳照片，不把“文件名日期”的中午占位时间当作精确时间。
同一日内按时间处理，最长跨度 12 小时、相邻间隔最多 3 小时。
每张新照片至少需要一个组内连接依据：

- 3 小时内、3 公里以内的已知定位；不要求画面相似。
- 1 小时内、20 公里以内的地点移动；不要求画面相似。
- 2 小时内出现同一人物候选（沿用已有严格人脸簇）。
- 45 分钟内内容相似度至少 0.72，作为缺少其他线索时的弱依据。

组内所有已知位置的两两距离不能超过 20 公里，防止地理位置不断传递扩张。
无定位照片不能绕开已有位置冲突。每一条连接保存来源照片、目标照片及依据，但公共结果不包含坐标或人脸向量。

这些是实验规则，不能识别真实摄影者，不能完全排除共享相簿中的不同人、不同活动混合；固定 UTC+8 的既有日期处理也没有在本轮重构。
旅程检测完全沿用旧规则。人物身份、跨年主题回忆和日期不足照片仍在原页面查看。

## 统一选片与去重

所有照片都使用本次 Ente MobileCLIP-S2 的完整向量空间，不借用旧 ViT-B-32 向量或旧向量阈值。
新去重规则只作用于本实验，不修改原 dedup/selector：

- 相同 SHA256 可以合并。
- 两张时间戳照片相隔不超过 120 秒，且内容余弦相似度至少 0.985，可作为近似重复。
- 同一时间窗内，余弦至少 0.94 且 dHash 汉明距离不超过 12，也可合并。
- 两张照片拥有不相交的人物候选时，不凭画面相似合并。
- 簇内两两满足条件，保留画质／美观／原回忆评分综合最高者，防止相似度链式吞并。
- 日期不同、时间不足的相似题材不直接去重；每张被合并照片都记录代表照片及原因。

去重后，按时间间隔和视觉相似性划分画面片段。组内选择综合画质、美观、原回忆评分，同时考虑尚未覆盖的片段、拍摄时间段和人物候选，并惩罚与已选照片过于相似的画面。
展示保持时间顺序，不自动编造“出发／高潮／结尾”等剧情。
默认预算约为去重后候选的 65%，同时不超过每个片段 1.5 个名额的总预算，最少 3 张、最多 12 张；少于三张不成册。
相似度、65%预算及各项权重均未经过人工标注校准。片段覆盖率不是质量评分。

## 人工验收入口

每侧点击“记录这一组”，可以：

1. 记录值得保留、混入无关照片、漏片、重复太多或封面不合适。
2. 对入选照片标记“不该入选”，对任意数据集照片标记“必须保留”。
3. 查看本组所有候选（包括被去重、没选中），或切换整个数据集找漏片，包括原基础过滤排除的照片。
4. 写下原因并保存。

记录绑定数据集、快照、方案和相册；不会自动改选片或训练偏好。没有由助手生成“用户标准答案”。
下一轮应先积累约 10–20 组用户认可样例，并在调参前划分调参集与留出验收集。
缺少这些标签时，不能报告真实的误混率、漏片率、身份准确率或声称整体效果已优于旧方案。

## 文件与运行

- 算法：`selection_lab/memory_experiment.py`。
- 页面：`selection_lab/static/memory-experiment.html`、同名 JS/CSS。
- 接口：`GET /api/memory-experiment`，`POST /api/memory-experiment-run`，`POST /api/memory-experiment-review`。
- 快照：当前数据集 `state/memory-experiment/<snapshot_id>.json`，不可变；`latest.json` 指向本类最新结果。
- 人工记录：同目录 `reviews.json`；重跑不覆盖旧记录。
- 校验记录：同目录 `verification.json`。

```sh
python3 tools/run_memory_experiment.py
python3 tools/selection_lab.py --port 8767 --view memories --open
```

重放脚本只使用缓存，检查重复运行一致性、旅程结果一致性、相册成员有效性，并确认原缓存／快照不变。本次校验了 22 个既有 JSON 文件内容未变。
服务仍只监听 127.0.0.1，图片预览复用去除 EXIF 的本地缩略图接口；未上传、未运行新的识别模型。
