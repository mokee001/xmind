# Onboarding Demo v2.2：全相册人物气泡与主题偏好

2026-09-11 根据用户截图要求修改。入口仍为 <http://127.0.0.1:8772/>，刷新现有页面即可。
只修改本地 Demo；不修改 App，不发布 TestFlight，不上传照片，不改用户已有偏好文件。

## 交互变化

- 人物入口直接显示圆形头像气泡，不再需要先展开“只看指定人物”。选中 `scale(1.1)` 并显示细外环，点击同一头像取消；没有卡片底板和勾选角标。
- 点击头像时复用已有 DOM 节点，避免替换元素导致缩放过渡失效；键盘按钮、`aria-pressed`、头像文字替代与减少动态效果偏好保留。
- 默认按完整图库唯一照片数降序显示 6 个人物组，更多按需展开，不随机凑数。头像来自整个人物组，界面不再用“几张精选”作为头像下的标签。
- 同页加入六类主题：毛孩子、出去玩的照片、吃到的好东西、山海与风景、看过的演出、逛过的展览。
  ID、名称与解释沿用 `photo-wall-app/App.js` 的主题选项；默认不选，可多选、可取消，不新增引导页面。
- 连接照片墙页面去掉用户图三标注的缩略图，保留设备名称、连接状态和网络说明。
- 仍是四步引导，默认全部精选、不选主题、不自动更新的顺利路径仍为五次点击，含一次权限弹窗确认。

## 人物来源与最终展示是两个范围

`tools/onboarding_preferences.py` 的 `library_people` 从当前快照的完整人物索引读取已归组人物，沿用 `effective_people` 的用户确认合并。
不调用 `preference_people` 做“精选中有照片才可见”的筛选；不改变其他页面的既有实现。

当前已有快照覆盖 677 张图库照片，确认合并后提供 38 个人物组，包含 34 个精选匹配为零的组。
这是已有识别结果，不是本次重新推理，也不保证 38 组均为 38 个不同的真实人物。未归组人脸不混入可选身份。

人物头像可来自非精选照片，但仅允许读取索引中的对应人脸裁剪；普通 `/photo/` 接口仍只能读取第一层照片。
图库、识别版本、用户确认合并及 Demo 偏好版本都绑定到本次 scope，变更后必须重新确认。

照片墙始终从第一层已入选照片中取图：

1. 未选择人物时，点击明确的“使用全部精选，生成预览”才确认范围；此前未授权展示。
2. 选择人物按任意一人匹配，再与第一层取交集。头像选中并不把其全部原始照片加入精选。
3. 人物没有精选匹配时显示原因；匹配不足当前模板 8 张时也提示，并阻止继续。可再选其他人物或明确点击“不限人物”。
4. 取消最后一个人物不静默恢复全部；保持空范围提示，直到用户作出明确选择。
5. 多人合照仍可能包含其他人物，成功匹配时提示需查看最终预览。

## 主题如何影响结果

这是独立的 Demo 展示安排版本 `onboarding-library-people-themes-v1`，不是基准选片权重升级。

主题映射只使用已保存、未隐藏相册的成员依据：

| App 主题 ID | 已保存相册 topic |
| --- | --- |
| topic-pets | pets |
| topic-travel | trip |
| topic-food | table |
| topic-scenery | outdoors |
| topic-stage | stage |
| topic-art | art |

在已经确认的人物范围内，把属于所选任一主题的照片稳定排到前面，其余仍保留，继续换组可以看到。
这实现“优先安排”，不声称概率采样，也不会重新打标、改精选分数、排除未选主题或引入范围外照片。
没有主题选择时沿用原顺序；所选主题在当前范围无证据时保留本次会话偏好并提示，原顺序不受影响。
当前快照没有合格艺术主题相册，所以“逛过的展览”可能提示暂无匹配；不借用其他图库或虚构标签。

`theme_ids` 随预览请求发送、校验并由结果回传；改变主题会取消旧预览确认，防止使用与新设置不符的结果。
全部偏好只在本次 Demo 会话中生效，刷新会重置；未加入真实自动更新调度器。
