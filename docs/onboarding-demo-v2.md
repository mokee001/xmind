# 首次引导 Demo v2.1：四步引导

> 本文件记录 v2.1；当前 v2.2 的全相册人物气泡、主题选择与边界说明见 [onboarding-demo-v2.2.md](onboarding-demo-v2.2.md)。

用户先要求默认路径五次点击，随后明确：“从引导来说应该是 4 步，现在拆得太碎了”。本轮按四个用户任务组织引导，不再把每次点击单独编号。只修改本地网页预览，未确认合入 App，未发布 TestFlight。

入口：<http://127.0.0.1:8772/>，旧页面刷新后使用 v2.1。启动方式仍为 `python3 tools/preview_onboarding.py`。

## 四个任务，不把弹窗和等待另算一步

1. **授权相册**：欢迎、用途说明和授权入口在同页；权限弹窗属于这一步，弹出或取消均不推进步骤。
2. **连接照片墙**：查找、找到、连接中与失败重试均留在连接页。
3. **展示设置**：范围、可选人物与更新安排在同页，后台整理不打断设置。
4. **预览上墙**：原页从准备中变成整墙预览，用户确认后进入当前展示。

侧栏、页面编号与进度条统一对应这四个任务。当前展示是完成后的页面，不是第五步。权限弹窗不再单独编号，没有增加页面或按钮；默认顺利路径仍为五次必要点击。

## 引导步骤与实际点击分开计算

默认顺利路径（全部精选、不自动更新）如下，包含权限弹窗本身的一次点击：

| 次数 | 用户点什么 | 随后发生什么 |
| --- | --- | --- |
| 1 | 开始并授权相册 | 直接出现权限弹窗，没有独立授权说明页 |
| 2 | 允许访问（模拟） | 进入连接页并自动寻找演示设备 |
| 3 | 连接这面照片墙 | 原页显示连接状态；成功自动进入展示设置 |
| 4 | 使用全部精选，生成预览 | 明确确认全部精选范围，以及页面上关闭的自动更新开关 |
| 5 | 确认并展示这组照片 | 只在完整预览就绪后可点击；再次校验版本后模拟上屏 |

第四次点击前 `mode` 为未确认，不会静默授权全部照片。自动更新默认 `off` 且 `scheduleConfirmed=false`；第四次点击才确认这个可见设置。第五次点击前没有模拟当前墙，也不需要额外勾选框。

指定人物、展开其余人物、改为定时更新、调整时间、换组、返回、失败重试均是额外操作，不能冒充仍然五次。真实 App 的蓝牙／本地网络权限、Wi-Fi 选择与密码输入也可能增加操作；本 Demo 使用明确标记的演示网络，不能据此承诺真实设备首次配置必定只有五次。

## 明白、短、保留控制

- 欢迎页合并相册用途与授权入口，保留一句情绪文案。隐私说明仍可查看。
- 连接页直接叫“连接照片墙”，用小设备卡显示查找／已找到／连接中／失败，不再放满屏大图或重复点击连接。
- 展示范围和更新时间在同一页。默认不自动更新；指定人物和每天更新时间按需展开。
- 限制人物时，无选择或人物尚未就绪不可继续，不回退到全部；多选仍是任意一人匹配，合照可能有其他人，页面明示。
- 预览页同时容纳等待和结果：同一画面位置由占位变成真实整墙，不新增等待页或“继续”按钮。失败时保留设置。
- 下一组只换整墙，停留只作用于整墙，不新增“不喜欢／不再展示”或人物排除信号。

正常整理时长 6.5 秒、快速 0.3 秒、慢速 60 秒均为模拟场景，用于评审流程，不是推理速度或性能提升。慢速场景可在折叠的演示控制中提前完成。
