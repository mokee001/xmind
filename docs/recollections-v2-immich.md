## 修复内容

1. `backend/dedup.py` 改为 `dedup-v2-corroborated`：相同文件 SHA256 可以判重；近重复需要 dHash 与非平坦灰度网格共同支持。不再单独按同类标签、粗灰度、CLIP 语义相近、相同文件名删除照片。组内两两符合证据，避免相似链或代表变更造成串组。旧审计 35 对“仅灰度＋大类”样本在新版全部不再自动删除；这是诊断样本结果，不是声称找回 35 张实际相簿照片。该策略更保守，也可能保留裁剪、调色等近重复图。
2. `backend/tagger.py` 的 auto／yolo 模式失败不再生成演示标签；只有明确 mock 模式才返回 demo。状态区分 complete（包括成功但没有目标）、failed 与 demo；记录可重试性、错误类别、模型、库版本、可取得的实际权重摘要及输入摘要。`backend/real_tagger.py` 不再在加载失败后偷偷换成 nano 模型。历史缓存未被重新打标，旧记录不能追认真实来源；本次并未新增自动重试调度器。
3. V2 使用已有 V1 的主题、旅行、质量权重和严格时间／图像去重规则；人物 membership 换为 Immich 完整索引。V1 原本没有上述粗灰度直接删除问题，因此未把旧实验台问题错误移植为 V1 问题。
4. 新页面可以查看真实照片、目标脸框、未归组人脸、最终精选播放，并可切回原版。人物标签明确为“待确认”，没有虚构名字或身份。
