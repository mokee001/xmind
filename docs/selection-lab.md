# 本地选片实验台

2026-09-08 已加入“共享相簿测试”：当前默认候选集为 **447 张**，通过 `outputs/selection-lab/active-dataset.json` 指向独立目录。旧 132 张缓存和快照原样保留。新结果、日期规则和回退方法见 [共享相簿导入记录](shared-album-import-2026-09-08.md)。下文的 132 张数量描述指最初的七月基线。

## 开始使用

双击项目根目录的 `启动选片实验台.command`，或在项目目录执行：

```sh
python3 tools/selection_lab.py --open
```

默认地址 `http://127.0.0.1:8766/`。同端口实验台已运行时会打开现有实例；不会停止其他占用端口的程序。关闭启动它的终端会结束服务，再双击可重新启动。需要 Python 3.9+ 和 Pillow；不需要启动线上后端、Docker、CLIP 服务或上传原图。

这是本地调试工具，不部署到 Sites 或其他云平台。当前读取 `outputs/immich-comparison/current-cache.json` 与 `immich-cache.json` 中的全部有效记录。初始样本是 132 张七月照片，原图只读。

## 已提供的能力

- “Ente 识别＋我的成册”是第三条独立链路：使用全体候选的 Ente 内容/人脸证据，复用项目过滤、去重与成册。447 张首次结果为 10 集、91 张，详见 [组合方案实验](ente-hybrid-albums.md)。没有覆盖原方案或 Ente 原版回忆。
- 首页新增“两套相册对比”（`http://127.0.0.1:8766/#compare`）：在同一候选集上并排展示当前方案与 Ente 自然回忆，支持封面总览、逐张对照、共同/差异筛选和原比例大图。详细口径见 [相册对比说明](album-result-comparison.md)。
- 首页默认是“为你精选”：大封面相册卡片，点开后按日期浏览、左右切换或自动播放。右上角可返回调参实验台。
- 相册集从全部合格候选中按月份、内容主题和日期分别独立选片，不是对全局 Top 20 再分组。每集至少 3 张，最多 12 张；不够就不生成，最多展示 10 集。
- 直接展示最终照片，支持纯照片视图、点击看原比例预览。
- 调整数量、主题、评分权重、画质门槛、CLIP/dHash 去重阈值、事件间隔和多样性；默认调参后自动重选，也可关闭自动重选。
- 每张照片显示实际处理阶段：基础非照片、历史内容复核、质量、主题、相似组、候选未入选、入选。
- 查看相似组最终保留的照片。去重使用生产代码的贪心分组，组内成员不保证与最终代表两两直接相似，不伪造某个判重距离。
- 查看评分各项贡献；综合分不是 MMR 多样性效用分，二者不混称。
- 保存结果快照、查看旧快照、恢复参数重新运行、对比新增/移出照片、导出快照。
- 记录误杀、重复、偏题等问题和备注；标记不改变算法、不自动训练线上偏好。
- 导入符合协议的 Ente 开发版结果；详见下文。

## 一次完整的调试

1. 打开默认结果，保存一个命名基准，例如“9 月 7 日 · 默认”。
2. 点击“不应该入选”的照片，标记问题；在“全部与淘汰”里寻找不该被排除的照片。
3. 每次先调一个维度。例如重复多就调去重；全是同一事件就调事件多样性；真实照片漏掉则先看具体淘汰阶段，不盲目降低全部阈值。
4. 从“我的方案”选中基准并点击“与当前对比”。相同结果是有效结果，不为了对比强制制造差异。
5. 满意后保存新方案。只保存本机快照，不覆盖 `config/selection_profiles.json`，更不自动发布。
6. 用未参与调参的另一批样本回归，再在真实 iPhone 上核验时延、断网、发热和后台中断。

问题标记是开发/验收行为，不是产品要求普通用户手工选照片。

## 引擎真实性与当前局限

### 精选相册集 v1（新增）

相册集使用真实 macOS 公共 Vision `VNClassifyImageRequest` 修订版 1 与 `VNDetectFaceRectanglesRequest` 修订版 3。先在本机处理方向校正、最长边 640 的缩略图，一次提取全部分类置信度与人脸数量，存于 `outputs/selection-lab/album-features.json`。这不是苹果相册的私有 Memories 模型，也不是 Ente 原版算法。

重新建立本机索引：

```sh
python3 tools/build_album_features.py
```

需要 Xcode / Swift / macOS Vision；没有可用索引时明确报错，不回退到模拟主题。已完成记录按照片 SHA256、数据集、预处理、系统版本与提取脚本摘要校验后复用。该工具只读取本机照片，不发起网络请求。

相册规则位于 `selection_lab/collections.py`：

- 沿用基础非照片、历史内容复核与画质过滤。新增 Vision screenshot ≥ 0.60、printed_page/receipt/passport/diagram ≥ 0.80、document ≥ 0.92 的非照片排除。它们仍是待真实样本验证的阈值，不保证零误判。
- 人物（people 或人脸佐证）、食物、城市/天空、猫狗和舞台分别需要对应置信度门槛。无依据不生成主题；人物只表示画面含人，不推断同一身份。
- 本批样本已有 `2026-07-DD__…` 命名，日期优先使用这个明确的样本日期；不会把原缓存中集中在导入日的时间当成真实拍摄时间。文件名仅精确到日时只做日分组，不伪造小时级活动；没有文件名日期时才使用标明未核实的缓存时间。
- 组内使用项目现有去重与选片函数；数量上限为 `min(12, 最终张数)`，按日期展示。封面从组内按美观、画质及主题相关性选取，已使用过的封面降权。
- 精选集之间允许照片复用；成员 Jaccard 重合度大于 0.85 的集合被抑制。合格照片不够 3 张时不拼凑相册。
- 右上角“调整选片策略”的变化会重新生成相册集。旧“最终照片”页仍是原有缓存 Top N 回放；人物等旧标签缺失会影响那一页，但不冒充新的 Vision 分类结果。两者是不同输出目标。
- 保存方案时同时保存相册完整快照；旧方案如没有相册快照，需要“恢复参数”重新生成，不能称其为旧版已有相册。

首批实跑 132 张本机 Vision 记录全部成功。默认规则得到 97 张相册候选，生成 10 个相册集，覆盖 58 张不同照片。这个数量是当前样本与规则的结果，不是质量目标。

### 原有全局 Top N 缓存回放

实验调用真实项目模块：`backend.curation.prepare`、`backend.dedup.duplicate_clusters`、`backend.selector.select_for_template`。不是浏览器里另写的一套排序公式。

但这是**桌面缓存回放**，不是当前 iPhone / 线上生产识别结果，也不是苹果或 Ente 的原版选片。首次特征提取已在此前完成，本次运行耗时仅表示策略回放，不包含原图扫描、模型下载、识别或传输。

当前缓存来源限制：

- 132 张图片向量记录的模型是 `ViT-B-32__openai`；大小、修改时间、模型名称、向量维数不符的缓存不会附着。
- 旧基础标签未记录具体检测器来源，不能凭这份缓存认定语义标签全部来自真实 YOLO。换用可追溯端侧特征是后续工作。
- 历史内容复核只留下 `outputs/new-strategy-preview/selected.json` 中的 11 张排除名单，没有提示词向量或逐张相似度。实验台按当前样本的唯一文件名关联，保留并标明历史来源；不是本轮 CLIP 实跑或可校准分数。其他照片集不要复用这份名单。
- 基础非照片/质量过滤已经把某些旧分数置零，无法靠调参恢复原始分数。要检验这层误杀，应重新提取原始特征并保留过滤前测量值，不得直接“解禁”所有零分图片。
- 偏好固定为中性 0.5，不加载生产用户模型。因此单独提高偏好权重不会产生“更懂我”的效果，只会影响其他分数与多样性惩罚的相对大小。
- 人物主题目前按标签筛选，不能保证是同一个人；事件目前是时间间隔分组，不会推断城市名称、亲属关系或节日。
- 内容签名去重仍按项目的固定阈值执行，CLIP/dHash 滑块不是“所有去重的总开关”。

## 数据、版本和复现

持久化目录：

```text
outputs/selection-lab/
  runs/<uuid>.json                     完整结果快照、配置、来源
  annotations/<dataset-sha256>.json    问题标记和备注
```

这些目录被现有 `.gitignore` 排除。保存采用独立 UUID 和原子替换，不覆盖已有方案。界面没有删除原图或批量上传入口。

照片 ID 使用原文件 SHA256 加路径区分后缀，避免重名覆盖。实验签名固定：照片集、特征版本（缓存文件摘要）、历史复核名单、代码摘要、归一化策略、测试日期、东八区、空展示历史。本版选片没有随机采样。

每轮运行检查源文件大小/修改时间；变化后拒绝继续使用旧索引。重新分析并重启实验台。该检查不是对恶意篡改的安全证明；初始索引会计算实际文件 SHA256。

“查看快照”展示当时结果，“恢复参数”使用当前引擎重新运行，不能把新版重跑称为旧版引擎的精确复现。严格跨引擎版本重现还需要保留对应代码和模型版本。

增加照片集时，先用现有特征提取流程生成独立缓存，再指定 `--cache-dir`、`--state-dir`。不要把来源不明或带占位语义标签的缓存当作模型质量结论。其他数据集不应应用七月复核名单，可指定一个不存在的 `--historical` 路径以不加载历史名单。

## Ente 接入：现在能做什么

已支持**固定版本 Ente 源码的本机实跑**，以及外部结果包导入。首页“Ente 原版结果”是独立入口，不再只是导入占位。详细环境、实际结果、缓存与调试方法见 [Ente 实跑说明](ente-lab.md)。

实验台有“Ente 接入”页，可以：

1. 下载当前照片清单（不含原图路径、原图或向量）。
2. 导入实际 Ente 开发版本按下述协议生成的 JSON。
3. 查看它的回忆分组、封面和原始照片顺序，保存为独立只读快照。
4. 与本项目结果比成员差异。两种引擎输出目标可能不同，不应仅以重合率评判优劣。

本机路径运行原版 Rust 识别 + Dart 人脸聚类 / Smart Memories 计算并自动保存快照；**不是完整手机 App 流程，也不是 iOS 性能测试**。普通 Ente App 的数据备份 JSON 不是下述协议。外部手动导入中的来源字段由导出方声明，本工具不认证其真实性。

### 结果包协议 v1

```json
{
  "schema_version": 1,
  "engine": "ente",
  "dataset_id": "从实验台照片清单复制",
  "provenance": {
    "commit": "实际 Ente 仓库的完整 40 位 Git 提交哈希",
    "app_version": "实际 App 版本",
    "platform": "ios",
    "generated_at": "2026-09-07T12:00:00+08:00",
    "model": "模型名称与版本或摘要；多个模型应全部记录",
    "exporter_version": "自建导出器版本",
    "mode": "natural"
  },
  "memories": [
    {
      "id": "Ente 中的回忆 ID",
      "title": "原版回忆标题",
      "photo_sha256": ["原文件 A 的完整 SHA256", "原文件 B 的完整 SHA256"],
      "cover_sha256": "原文件 A 的完整 SHA256"
    }
  ]
}
```

约束：

- `mode=natural` 表示原版自然输出；`debug_all_candidates` 表示调试展开全部候选。必须标明，不能混称。
- 原文件 SHA256 必须唯一匹配当前清单；不按文件名猜、不静默跳过未知照片。iOS 导入若发生转码，需在准备测试集阶段核对原始资源，不能用转换后哈希冒充原文件。
- 完全相同的多个文件副本会导致匹配歧义，v1 拒绝导入这些歧义成员；后续可扩展明确的资源 ID 映射。
- 保留组内顺序、封面和跨组重复；首页平铺按首次出现去重，组内视图不重排。
- 空 `memories` 合法；没有自然回忆不会补成我们的 Top 20。
- 不接收图片、向量或任意文件路径。最大请求 2 MB，最多 200 组、每组 500 张。
- 导入照片详情的基础画质/标签来自本项目缓存，不是 Ente 模型得分。原版结果如含截图，会按真实快照显示，便于观察其与本项目照片-only要求的差异；不能称其通过了我们的最终输出审核。

## 隐私边界

服务只监听 `127.0.0.1`，校验 Host、跨站来源和写请求令牌；不配置 CORS、不加载 CDN、不给浏览器发送原图路径。缩略预览由 Pillow 生成，不附带原 EXIF/GPS。没有照片上传接口。Ente 首次准备需要联网下载源码、工具链和模型，识别和回忆计算使用本地文件；Dart 回放禁止 HTTP 客户端创建。

本机快照包含文件名、标签和选片记录，仍属于隐私数据；“不上传”不代表“不在本机留存”。运行目录权限受当前用户控制，数据文件尽量设置为仅当前用户可读写。请勿把本工具通过代理或端口转发暴露到公网。
