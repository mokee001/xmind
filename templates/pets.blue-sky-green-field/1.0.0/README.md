# 蓝天绿地拼贴 v1.0.0

最新规则确认日期为2026-10-19，规则版本为blue-sky-generation-rules-v3，结构化规范见[generation-rules.json](generation-rules.json)。适用主体为猫、狗、仓鼠、鹦鹉、乌龟、金鱼等常见宠物，物种示例不是封闭白名单。运行代码已同步标准版与兜底版：硬性要求决定资格，按姿态偏好、构图与边缘偏好、原片通用评分逐级排序；不足时依次隐去槽位，零张仍输出模板背景成品。模板档案版本继续为v1.0.0。

视觉基线为已批准的布局v5、描边v3；原1号、2号猫批准样例保留。当前运行版本为选片策略v3、宠物证据v2、原片提示词v4及抠图验收v2。已完成离线规则/网关/加工/原生PNG测试及iOS17模块编译；真实多物种模型识别、身份判断、原生分割精度与iPhone性能仍待验证。模板状态保持validatingAutomation，不将编译或合成样本测试当作真实识别准确率或生产ready。

## 适用范围与输入

- 主题为宠物，适用于猫、狗、仓鼠、鹦鹉、乌龟、金鱼等常见伴侣宠物，不限于猫，也不限于上述六类；是否纳入宠物主题仍由上游已确认的主题规则决定。
- 正式输入来自上游已经准入的宠物相册；本地测试使用明确复核的校准样本。照片权限、抓取数量、iCloud 下载、生成后上屏不在模板内处理。
- 标准版使用5张不同原照片，入选主体必须为同一只宠物；指定目标宠物时仍应对应该目标。同一物种或相似外观不等于同一个体。除明确的硬性要求外，原有构图、姿态、边缘、单主体及技术审美条件均按偏好排序，不因偏好不满足而拒绝入选。
- 兜底版允许0～4张用户照片，按指定顺序隐藏无法填满的槽位；不重复同一照片凑数，也不改用其他宠物凑数。
- 规则判断与评分针对未抠图原照片；初步入选后才抠图，不能先批量抠候选池。

## 标准版：硬性要求与偏好

共用硬性要求为宠物主体身份一致，照片不得重复；通用准入在模板之前完成，不被模板兜底绕过。硬性身份未知不能当作符合，偏好不满足、未知或不适用当前物种时不能成为取消资格的理由。一般模板允许硬性要求为空，但本模板保留同一只宠物的要求。

| 槽位 | 构图与边缘偏好 | 姿态偏好 |
| --- | --- | --- |
| photo1 左上 | 宠物头部/面部大且突出；主体上、下、右边缘完整 | 无额外姿态偏好 |
| photo2 右上 | 全身完整，四边完整 | 俯拍、蜷曲 |
| photo3 左下 | 全身完整，四边完整 | 正面站立或坐立 |
| photo4 中部 | 全身完整，四边完整 | 正面站立或坐立 |
| photo5 右下 | 半身近景，宠物头部/面部清晰突出，上、左边缘完整 | 无额外姿态偏好 |

单一明确宠物主体、基本清晰度、曝光与抠图条件也作为模板内的偏好/质量维度；已经在准入中明确排除的照片不能因此重新进入候选。边缘按正确朝向的原画面独立判断，完整头部不能代替完整身体；自然自遮挡不等于画框截断。没有启用镜像、补图或重建主体。

俯拍指相机在宠物上方向下拍摄，包括斜俯拍，无需严格垂直鸟瞰；宠物抬头、面对镜头、露出正脸不构成否定依据。综合身体及周围环境的透视，不以地板可见、宠物躺着或画面旋转单独推断，不设角度阈值；视角与蜷曲、全身及边缘条件分别判断。

姿态偏好按物种与实际身体结构解释：蜷曲、正面站立或坐立等不适用当前物种时记为不适用，不当作不合格，也不人为要求金鱼站立、乌龟蜷曲。不适用项不作扣分或淘汰依据；跨物种可比评分和适用偏好的归一化细节尚未另行约定，不自行添加替代姿态或猫专属门槛。

七项评分均为1～5分，缺证据用null：主体清晰20、曝光10、色彩自然10、抠图可行性10、神态与亲近感20、生活感20、趣味性10。总计100，技术/审美各50。没有增加总分淘汰线、品种偏好或原生数值阈值。

在满足硬性要求的候选中，按整组方案依次最大化姿态偏好命中数、构图与边缘偏好命中数、已知通用评分总和；完全相同则按稳定照片ID确定结果。每个层级内适用且明确命中的偏好各计一次，不在不同层级之间做加权相抵；姿态一项的优先级高于任何下一层的累计加分。singlePetSubject作为主体构图偏好，technicalBasics由七项通用质量评分体现，不额外增加二元奖励或淘汰门槛。偏好未知/不适用不计命中；评分未知保持null、不补0或默认3，也不取消满足硬条件照片的资格。计划中的通用总分仅累加已知完整评分，并保留证据待处理标记。

以槽位组合为单位联合分配，不贪心占用同一照片，不依赖输入顺序。偏好无法满足时，仍从满足硬要求的照片中排序填满五槽，这属于标准版。

同一宠物的身份证据只检查实际使用的照片；n张照片对应n×(n−1)/2个直接同一个体照片对，不依赖相似度或传递推断。指定宠物时，各入选照片另需与参照照片有直接同一个体证据，参照图不必最终入选。零张用户照片不需要身份、原片评分、抠图或照片验收调用。

## 兜底版：依次隐去槽位，零张也生成

只有满足硬性要求的不同照片无法填满标准版时，才触发兜底。固定隐去顺序为photo4 → photo3 → photo2 → photo1 → photo5；逐个隐去，直到剩余槽位能够完成不重复的硬条件分配。未达到偏好不是触发原因。

| 可用不同照片数 | 隐去槽位 | 保留槽位 | 输出 |
| --- | --- | --- | --- |
| 5张及以上 | 无 | photo1、photo2、photo3、photo4、photo5 | 标准版 |
| 4张 | photo4 | photo1、photo2、photo3、photo5 | 兜底版 |
| 3张 | photo4、photo3 | photo1、photo2、photo5 | 兜底版 |
| 2张 | photo4、photo3、photo2 | photo1、photo5 | 兜底版 |
| 1张 | photo4、photo3、photo2、photo1 | photo5 | 兜底版 |
| 0张 | 全部五槽 | 无 | 无用户照片的背景成品 |

隐去槽位时一并隐藏该照片生成的描边，不显示空框、占位符，也不拿Figma样例宠物图填充；其余照片槽位的位置、尺寸、旋转和层级不变。零张时仍按1800×2400画布输出模板原有背景及固定装饰图层，保留它们的几何和叠放，不包含任何用户照片或照片描边。照片数量不足，包括零张，不作为拒绝输出成品的理由。

自动流程优先选择能够完成标准版的模板；手动指定模板后，在同一模板内尝试标准版与兜底版。后续每个模板创建时都必须同时定义这两套方案，具体硬条件、偏好、排序及兜底规则独立配置。

## 运行实现与验证范围

- EchooCore：isPet为共同照片硬条件；选中照片不重复，实际使用照片逐对满足同一宠物证据，指定参照约束继续生效。所有原构图、边缘、单主体与技术审美条件不再作为额外选片硬门槛。先尝试完整五槽，再按固定顺序隐去，得到standard、fallback或backgroundOnly方案；证据未知保留标记，不冒充照片不合格。
- EchooApple：ApplePetCutout使用物种通用的前景实例分割；只有入选照片才加工。BlueSkyGenerationEngine接收上游已经准入的宠物相册、资源、版本匹配的原片证据及后端验收闭包；替换不可用照片后重选，最终允许背景成品。原生框架失败、资源仅在云端、目标不明确或验收未知不能伪装为通过。用户取消任务仍按取消处理。
- 抠图验收：只以correctSubject、anatomyPreserved、backgroundRemoved作为加工通过条件；四方向完整性继续报告，但只参与原照片构图偏好，不作为抠图后的隐藏硬门槛。响应绑定请求/预览/PNG摘要；主体错误、加工误删、未去除背景或证据未知时使用其他候选，候选耗尽后继续隐去。没有修改原照片评分、准入或主题标签。
- 渲染：原生CoreGraphics支持0～5张，隐藏槽位不画照片及描边，不改变其余槽位几何与固定装饰层级。零张不请求照片资源、不抠图、不调用照片评分/身份/验收API，仍输出1800×2400背景成品。
- API：所有千问调用固定为qwen3.8-flash；原片提示词v4、抠图提示词v2随gateway-strategy.json归档。原片证据版本blue-sky-pet-v2使用isPet、singlePetSubject、头部通用事实及notApplicablePreferences；旧猫证据版本不被重标为新结果。提示词版本进入缓存键，未知/失败不缓存成成功。厂商凭证仅属于后端，原片使用有界SSE完整回复，不记录回复片段、私密文本或密钥。
- 入口：本地复核页支持可变入选数量与隐去列表，展示分层偏好命中数和未知评分；空样本直接生成背景，API key可留空使用背景功能。显式操作才调用模型，恢复不重放。旧targetCat字段仅兼容迁移参照ID，不迁移旧模型事实。人工分组/复核与模型原始证据分别保存。
- 模板路由：已注册且通过产品验证的生成器可声明minimumPhotoCount=0供手动空相册生成；自动路由用已有证据优先standard方案，不为选择模板扫描整库或启动模型。BlueSkyArtworkGenerator默认状态仍为validatingAutomation，宿主完成生产验证后再注册。

七类物种示例（含开放范围示例兔子）×0～5张的42个离线契约用例通过，并实际生成六张不同的1800×2400 PNG；这些使用合成事实与透明形状，不是识别/身份或真实分割精度测试。已有两组猫图视觉批准仍只适用于那些样例。人物手臂等前景保留规则未额外扩展，真实多物种能力与真机性能仍需验证。

## 文件与复现

- generation-rules.json：2026-10-19确认并同步到运行代码的常见宠物范围及标准版/兜底版规则v3，与当前运行参数和分发代码一致；历史用户原文中的“猫”保留作审计，后续宠物范围确认优先。
- template.json：从当前Swift运行参数导出的物种范围、规则、版式、描边及验证状态。
- assets.json：六个随包原始静态资产的尺寸与SHA256。
- gateway-strategy.json：型号、提示词版本、实际提示词和结构化契约。
- approval.json：视觉覆盖授权、最新规则确认、两组最终成品字节摘要及被替换版本的标识，不包含私人照片。
- runtime-files.json：本版本代码/测试文件清单和摘要；SHA256SUMS验证整个分发包。
- 分发包的runtime/为独立Swift Package与Python网关源码；静态资源位于runtime/Sources/EchooApple/Resources/BlueSky/。

在runtime/运行sh scripts/test-swift.sh、sh scripts/check-ios.sh；在runtime/gateway/运行python3 -B -m unittest discover -s tests -v。真实测试需宿主提供照片及后端凭证。模板包不带任何默认图库、密钥或私人示例成品。

本机相似度仅用于测试样本建议，不作为宠物身份依据。能力说明见[Apple Vision](https://developer.apple.com/documentation/vision/vngenerateimagefeatureprintrequest)。
